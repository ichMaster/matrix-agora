## Findings

### 1. 🔴 An unfit memory gist loops — `agents/agent.py` `_memory_gist_tick`
**Scenario:** the gist comes back unfit: `BANNED_RE` matches («модель Всесвіту» suits an astronomer), Flash declines to
shorten an intimate memory, or the result is empty. The code logs and returns with no back-off and no mark. The next
talk check, 30 s later, picks the same memory again. 10 checks made 10 `memory_gist` calls, which is ≈ 2,880 a day,
each with her whole canon as the system prompt. Every later memory's gist waits behind it.
**Fix:** an unfit result writes an empty `<key>.gist.md`. The memory then shows its first sentence, and the file's
existence ends the retries.

### 2. 🟠 Failures retried for good — `_gist_tick`, `_talk_digest_tick`
**Gists:** `complete` returns None both on a network failure and on a prompt-stage block. `_gist_tick` waits 10
minutes and tries the same oldest gist again: one blocked day made 144 calls a day. Every later day's gist, every
week's and every memory's gist waits behind it. The summaries solved this with `TALK_FAILS_MAX`.
**The digest:** a batch Flash blocks is retried every 10 minutes until her midnight. No later batch folds that day, and
the lines between the fold point and the capped window reach neither the prompt nor the digest.
**Fix:** count the failures per gist and per batch. After `TALK_FAILS_MAX` (3), a gist is written empty, and a batch
is passed over: the fold point moves on and the digest text stays.

### 3. 🟠 The fold's lines and the window's cap — `_open_private_lines`, `_gemini_lines`, `_talk_digest_tick`
**Scenario:**
- **A small `HISTORY_N`:** the fold reads the archive's last `HISTORY_N` lines. With `HISTORY_N` below n + batch,
  nothing ever folds, and her day's earlier lines drop out of her prompt.
- **A fold far behind:** after an outage the fold can be more than `HISTORY_N` lines behind; it skips the lines it
  cannot see.
- **`PRIVATE_HISTORY_N`:** the owner's cap still applies after the `lumi` window. Any value below n leaves lines in
  neither place.

**Fix:**
- The fold reads every open line after its point (`private_between`), with no count.
- The window reads at least n + batch lines.
- In `lumi`, `PRIVATE_HISTORY_N` does not cut the window.

### 4. 🟡 Same-second lines at a batch's end — `_talk_digest_tick`
**Scenario:** his Telegram lines carry a time to the second. If a batch ends on the first of two lines with the same
time, the fold point is that time, and the second line fails both `> upto_ms` tests: it is in neither the window nor
the digest.
**Fix:** a batch never ends inside a run of lines with the same time; it takes the rest of the run.

### 5. 🟡 A week gisted from nothing — `_gist_tick`
**Scenario:** every talking day of a week got an empty gist (blocked thrice). The week is still due, `gist_items`
gives `[]`, and Flash is asked to write a line from an empty list, which risks an invented memory.
**Fix:** with no items, the gist is stored empty, with no call.

### 6. 🟡 «By memory»'s numbers — `agents/usage.py`, `agents/agent.py`, `agents/llm.py`
**What is missed or skewed:**
- **The checks:** the `talk_check` probes after each fold and gist run on Pro, but cannot be told from the layered
  summaries' own checks, so `lumi`'s cost an answer is understated.
- **The time:** `time_median` is the last round's alone.
- **`tool_calls`:** it counts the calls answered «більше нічого».
- **The `embed` lines:** the recall tool's lines run inside the answer and carry its `prompt_parts`, making a false
  «structure» group.

**Fix:**
- `lumi`'s checks get their own kind, `lumi_check`, counted with the mode.
- The recall rounds' time is reported an answer (`recall_ms`).
- `tool_calls` counts the calls run.
- `prompt_parts` go on answer lines and recall rounds alone.

### 7. 🟡 Function-calling edges — `agents/llm.py` `_recall_rounds`
**Scenario:**
- **A round that fails** (say the cache expired mid-answer) is silence. The first call has a retry without the cache;
  the rounds don't.
- **A model that asks again after «більше нічого»** ends in `_empty`, which is silence.

`tool_config` cannot be sent beside `cached_content`, so there is no clean switch-off.
**Home:** backlog. Both are rare; read them in the measures (`<kind>_recall` lines with no answer after them).

### 8. 🟡 Scope and cosmetics
**Scenario:**
- **Memories in one line everywhere:** in `lumi` mode `memories_section` gives one-line memories to her Agora and
  backup prompts too. That fits «her memory as Lumi's», but it is wider than her private prompt.
- **A stale digest:** after a switch back to `layered`, the panel still labels the last digest «today».

**Home:** backlog — to see in the days of talk.

## What's solid

- **The function-calling loop:**
  - The follow-up's first turn is the transcript the first call sent; in `lumi` the cache holds the start alone.
  - The model's turn goes back as it came, so thought signatures are kept.
  - `Part.from_function_response(name=, response=)` matches the SDK.
  - The tools live in the cache alone and never ride beside `cached_content`; the plain retry resends them.
  - `LAST_BLOCK` and the refusal check apply to the final answer, and `TOOL_CALLS` is scoped.
  - The cache's fingerprint takes the tools.
- **The window and the fold** agree in normal use, with no double fold. DST and her midnight are read by her local
  dates.
- **The gists:**
  - `_bands` and `gists_due` hold across DST and week ends, and today is never gisted.
  - A written gist is never rewritten, and closing a line clears the summaries over it as before.
  - The gists never starve behind the summaries.
- **The mode switch:** a member without a private chat is always `layered`, and the `_append_usage` closure is right.
- **Invariants:**
  - no text in any new log line;
  - the tools' names, descriptions and results never call her a model;
  - `day_talk` gives nothing for a day not yet come;
  - the digest, the recall and the summaries read only lines open to Gemini, with softened lines left out.
- **`layered`** prompts are byte for byte as before. Only the cache planner's #9 changes `layered`, as intended.
