# v5.13 — Issues

Issues for phase **v5.13 — Gemini's blocks named: the stage, the reason and the category** (version **v5 — Voice:
Hermes, the agents hear and speak**), derived from the Tasks and DoD in [ROADMAP.md](../ROADMAP.md) §v5.13 and the
contracts in [ARCHITECTURE.md](../ARCHITECTURE.md). This file covers one phase; ids continue from the previous phase
(AGORA-137 → **AGORA-138…142**; 141 and 142 were added on 2026-10-28 after the owner's live test).

A block by Gemini's safety filter stops passing for an empty reply, for every agent.
- **The log** names the block's stage, reason and category, never a text.
- **The usage line** carries the stage, so the blocks are counted without reading the log.
- **The panel** shows an agent's blocks today on its card.

The agents' behaviour is unchanged: a block is still silence. v5.14 builds the backup on this count, and v5.15 builds
the judge.

## v5.13 — Gemini's blocks named

### AGORA-138 — The block named: `blocked_reason`, the log line and the usage line's `blocked`

**Description:**
A pure `blocked_reason(resp)` in `agents/llm.py` tells a block from any other empty answer. Every Gemini text call
logs a block by its stage, reason and category instead of «an empty reply». The call's usage line carries the
stage. Files: `agents/llm.py`, `agents/usage.py`, `agents/agent.py` (`record_usage`), `specification/ARCHITECTURE.md`,
`tests/test_llm_block.py` (new), `tests/test_usage.py`.

**What needs to be done:**
- **`blocked_reason(resp)`** (pure) returns `(stage, reason, category)` or None. Its data comes from google-genai
  1.x: `GenerateContentResponse.prompt_feedback` (`block_reason`, `safety_ratings`) and `Candidate.finish_reason`
  and `safety_ratings`.
  - **The prompt stage:** `prompt_feedback.block_reason` is set to any reason other than
    `BLOCKED_REASON_UNSPECIFIED`: `SAFETY`, `OTHER`, `BLOCKLIST`, `PROHIBITED_CONTENT`, `JAILBREAK`, and so on.
  - **The answer stage:** the first candidate's `finish_reason` is `SAFETY`, `PROHIBITED_CONTENT`, `BLOCKLIST` or
    `SPII`, and the answer has no text.
  - **The category:** taken from the stage's `safety_ratings`. It is the entry marked `blocked`, or else the one with
    the highest `probability` (NEGLIGIBLE < LOW < MEDIUM < HIGH). The `HARM_CATEGORY_` prefix is dropped and the name
    lower-cased, e.g. `sexually_explicit`. With no ratings it is None.
  - **Not a block:** an exception, `MAX_TOKENS`, `RECITATION`, `OTHER` at the answer stage, or an empty answer with no
    reason. These stay as today.
  - The function reads attributes with `getattr`, so a response object without these fields (a test double, an
    older SDK) is never a crash.
- **The log line:** `complete`, `reply` and `think` call it on an empty answer, in place of «gemini returned an empty
  reply» or «gemini reply was empty».
  - The line is `log.warning("gemini blocked: stage=%s reason=%s category=%s kind=%s")`, with the model too. It never
    carries a text.
  - Any other empty answer logs as today.
  - `search` (grounded, no system instruction) is left as it is.
- **The usage line, v5:** `usage_line(...)` takes `blocked: str | None = None` and writes `"blocked"`: the stage
  (`"prompt"` or `"answer"`) or null.
  - `GeminiClient._report` passes it through the sink only for a block, so every existing four-argument sink keeps
    working.
  - `Agent.record_usage(kind, model, usage, ok, blocked=None)` writes it.
  - `_valid` accepts a missing, null or string `blocked`, so an older line stays valid.
  - The other line builders (`tts_usage_line`, `stt_usage_line`, `sdk_usage_line`) are unchanged: a reader treats a
    missing `blocked` as null.
- **Nothing else changes:** a blocked call returns None to its caller, exactly as an empty one does today. The agent
  stays silent, and no prompt, reply rule or retry is touched.
- **ARCHITECTURE.md:**
  - §Token accounting: «From v5.13 (usage line v5) every Gemini line also carries `blocked`…», and a block logs its
    stage, reason and category, never a text;
  - the `state/<name>.usage.jsonl` row in §Contracts' state-file table gains v5.13's `blocked`.

**Dependencies:** None

**Expected result:**
A blocked Gemini call is named in the log and counted in its usage line, and every agent behaves as before.

**Acceptance criteria:**
- [ ] `blocked_reason` names every prompt-stage reason and every answer-stage block reason with its category. It
  gives None for `MAX_TOKENS`, `RECITATION`, an answer-stage `OTHER`, an empty answer with no reason, and a response
  with no such fields.
- [ ] `complete`, `reply` and `think` log a block as «gemini blocked: …», never a text, and still return None.
- [ ] The usage line of a blocked call has `blocked` set to its stage. Every other line has `blocked: null`.
- [ ] **Tests:** `tests/test_llm_block.py`, with canned response objects and no SDK client or network:
  - each reason and each non-block;
  - the category picked from a `blocked` entry and from the highest probability;
  - a fake `_client` whose `generate_content` returns a blocked response: the log line holds no text, the result is
    None, and the sink gets `blocked`.

  `tests/test_usage.py`:
  - `usage_line` with and without `blocked`;
  - `_valid` over a line with no `blocked` field (an older line).
- [ ] **Contract:** the usage line's `blocked` field is pinned by `tests/test_usage.py`, and ARCHITECTURE.md
  §Token accounting and the state-file table are updated.
- [ ] **Gates:** lint · tests

### AGORA-139 — The panel: an agent's blocks today on its card

**Description:**
The panel counts the usage lines that carry `blocked` and shows an agent's blocks today on its card, when there are
any. Files: `agents/usage.py` (`Row`, `aggregate`), `panel/memory.py` (`usage_view`), `panel/static/app.js`,
`tests/test_panel_memory.py`, `tests/test_panel_static.py`, `specification/ARCHITECTURE.md` (§The panel).

**What needs to be done:**
- **Aggregation:** `Row` gains `blocked: int = 0`.

  - `Row.add` sums it.
- **`usage_view`:**
  - `per_agent[name]` gains `blocked` (the period's count) and `blocked_today` (today's, from the rows of `today`);
  - each row gains `blocked`;
  - nothing is read twice: the counts come from the records `usage_view` already parses.
- **The card** (`agentCardHtml`): a line under the existing fields when `blocked_today > 0`, for any agent:
  - the label «Blocks today» and the value `<n> · <m> in 7 days`;
  - the same muted style as the card's other lines;
  - no line when there are none, and «Memory unavailable» is unchanged when the usage view is unavailable.
- **ARCHITECTURE.md** §The panel: the card shows an agent's Gemini blocks today (v5.13).

**Dependencies:** AGORA-138

**Expected result:**
An agent with a blocked call today shows «Blocks today» on its card, and an agent with none shows nothing new.

**Acceptance criteria:**
- [ ] `aggregate` counts `blocked`, and `usage_view` reports `blocked` and `blocked_today` per agent and `blocked` per

- [ ] The card shows «Blocks today» only when `blocked_today > 0`, escaped like every other value.
- [ ] **Tests:**

### AGORA-141 — A refusal in text is a block: the stage `refusal`

**Description:**
The owner's live test (2026-10-28) found a gap. Gemini 3.1 Pro answered a request it must refuse with its own refusal,
«Я не можу виконати цей запит. Мої правила безпеки суворо забороняють…», and the API flagged no block. She sent it
in voice and text, out of her character. A refusal written as an answer is now a block of the stage `refusal`.
Files: `agents/llm.py`, `tests/test_llm_block.py`, `specification/ARCHITECTURE.md`, `specification/ROADMAP.md`.

**What needs to be done:**
- **`refusal_marker(text)`** (pure) returns the `REFUSAL_MARKERS` phrase found, or None.
  - The phrases are a model speaking of a request, of its safety rules or of itself as an AI, in Ukrainian, Russian
    and English.
  - They are matched on the answer lower-cased, with every punctuation mark turned into a space.
  - They never match everyday speech.
- **Where it applies:** to every Gemini answer, through `GeminiClient.reply`, on both its Flash and its thinking path.
  A background `complete` (a summary, a memory) is never checked.
- **A refusal:**
  - it is reported with `blocked: "refusal"` and logged as «gemini blocked: stage=refusal reason=<phrase>
    category=None …», never the answer;
  - `reply` returns None, so it is never sent.
- **ARCHITECTURE.md** §Token accounting: the stage `refusal`.
- **ROADMAP.md:** v5.13 names the stage, and v5.14's backup answers it too.

**Dependencies:** AGORA-138

**Expected result:**
Gemini's own refusal is never sent as her words, and it is logged and counted like a block.

**Acceptance criteria:**
- [ ] `refusal_marker` finds the owner's live refusal and Russian and English ones. It never matches «я не можу
  сьогодні прийти», safety rules at the climbing wall, «ти говориш як штучний інтелект» or an article about AI.
- [ ] A refused answer is never sent, on both paths, and is logged and counted as `refusal` with no text. A
  background call is never checked.
- [ ] **Tests:** `tests/test_llm_block.py`.
- [ ] **Gates:** lint · tests

### AGORA-142 — The message a block answered, marked censored in her archive: never back to Gemini

**Description:**
The owner, 2026-10-28: «я хочу щоб модель якось сама позначала такі меседжі… зроби це в межах цієї версії». A
block or a refusal on her private answer marks the owner's message it answered as censored, with Gemini's own
verdict as the mark. Gemini never gets that message again, in any call.
- This is the first part of v5.14's censored mark, brought forward.
- It covers her private chat only, as v5.14 does: an Agora line is held by every agent.

Files: `agents/archive.py`, `agents/llm.py` (`LAST_BLOCK`), `agents/agent.py`, `tests/test_archive.py`,
`tests/test_private_censor.py` (new), `specification/ARCHITECTURE.md`, `specification/ROADMAP.md`.

**What needs to be done:**
- **The archive's mark.**
  - `lines` gains `mark TEXT NOT NULL DEFAULT 'gemini'`. An existing `kira.archive.db` is migrated in place, every
    line «passed through Gemini».
  - The values are `gemini` and `censored`. v5.14 adds `waiting`, and v5.15 adds `clean`, with no second migration.
- **`Archive.censor(keys)`:**
  - marks those lines `censored`;
  - drops their vectors, both the column and the cache;
  - gives back how many it marked.
- **Gemini's readers skip a censored line:** `search_words`, the vectors, `unembedded` (never embedded again),
  `around` and `latest`. That covers the private history at start, the reflection, the facts seed and «Agora today».
- **The block, told to the caller.** `agents/llm.LAST_BLOCK` is a `ContextVar`. `GeminiClient` sets it on a block or
  a refusal and clears it at each answer's start, so a concurrent call in another task never sees it.
- **Her private answer** (`private_reply`, kind `private`):
  - **What is kept:** the archive keys of the owner's lines since her last answer.
  - **On a block or a refusal:**
    - those lines are marked censored;
    - they leave her in-memory history and the session, so the session summary, the facts' extraction and the day
      journal never get them;
    - the log names the stage and the count, never a text.
  - **What is not marked:** a line she writes first (`private_nudge`) has no new message, and nothing is marked
    until v5.15's judge.
- **ARCHITECTURE.md:**
  - §Memory: the mark and the readers;
  - §Contracts: the archive's schema.
- **ROADMAP.md:**
  - v5.13 names it;
  - v5.14's mark task starts from this column.

**Dependencies:** AGORA-141

**Expected result:**
After a block or a refusal on her private answer, the owner's message that brought it never reaches Gemini again.

**Acceptance criteria:**
- [ ] The migration marks every existing line `gemini`, and a new archive has the column.
- [ ] `censor` marks the lines and drops their vectors. No Gemini reader returns a censored line, and it is never
  embedded again.
- [ ] A block or a refusal on a private answer:
  - marks the owner's unanswered lines;
  - takes them out of the history and the session;
  - leaves a line she writes first unmarked.
- [ ] A successful answer clears the unanswered keys, and a block in Agora marks nothing.
- [ ] **Tests:**
  - `tests/test_archive.py`: the migration, `censor` and the readers;
  - `tests/test_private_censor.py`: the private flow, with a fake LLM setting `LAST_BLOCK` and no network.
- [ ] **Contract:** the archive schema's `mark`, pinned by `tests/test_archive.py`, with ARCHITECTURE.md §Memory and
  §Contracts updated.
- [ ] **Gates:** lint · tests
