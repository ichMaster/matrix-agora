### #1 — unpinned image
**Failure scenario:** months later the host reboots (or v3.2's deploy runs `compose pull`); `latest` now points at a Continuwuity with a breaking storage change; the homeserver fails to start or migrates irreversibly — with `agora.lan` unchangeable without wiping the DB.
**Anchor:** `server/docker-compose.yml:3`.
**Proposed fix:** pin by repo digest of the exact image now running (`@sha256:c9c62bc5…`, version 26.9.1), keep the mirror note, document the conscious-upgrade path; mirror the pin into the ROADMAP §v0.1 snippet so spec = reality.

### #2 — first-account registration instruction wrong
**Failure scenario:** in v0.3 the owner types the configured `REGISTRATION_TOKEN` into Element; Continuwuity rejects it ("the token you set will not function until you create an account using the token above"); the phase stalls on a wrong instruction.
**Anchor:** `specification/ROADMAP.md` §v0.3 Tasks.
**Proposed fix:** document reality: the first account registers with the one-time bootstrap token from `docker compose logs homeserver` on the host; `REGISTRATION_TOKEN` applies from the second account (the bots in v0.4).
