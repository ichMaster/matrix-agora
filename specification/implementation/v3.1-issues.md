## v3.1 — Token accounting and report

### AGORA-024 — Usage accounting in the LLM seam, one line per call
- `GeminiClient` takes a sink; every call (ok, empty, or raised) reports kind + `usage_metadata`.
- Each call site names its kind: `reply`, `summary`, `plan`, `day_memory`, `digest`, `today`.
- The agent appends `{ts, agent, kind, model, prompt_tokens, output_tokens, total_tokens, ok}` to
  `state/<name>.usage.jsonl` (0600) — no texts; missing metadata → nulls; a write error is logged only.
- **Contract:** the usage line + the kind list (adds `digest`) — ARCHITECTURE updated with the pinning test.
- **Tests:** metadata parsing incl. missing fields, ok/failed calls, no text in the line, kinds per site.

### AGORA-025 — The usage report command
- `agents/usage.py` (pure: parse with corrupt-line skipping, aggregate by day × agent × kind, cost from
  `.env` prices, render plain or markdown) + `agents/usage_report.py [--days N] [--since YYYY-MM-DD]
  [--markdown]`; no files → "no data"; no prices → no cost column.
- **Tests:** aggregation sums, cost math, price absence, corrupt/empty/missing files, window filters.

### AGORA-026 — Live accounting + report run (DoD)
- After a live conversation both `usage.jsonl` files hold one line per call; the report's sums match.
