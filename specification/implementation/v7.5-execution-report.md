## Detailed Results

### AGORA-255: the order
`instruction_and_start` puts the start first — canon → life → memories → plans → mood → last-session memory → facts
→ talk — and then the tail: time → today → thoughts → past life → nudge → Agora today → recall → brief → move →
questions → voice → rules. `slow_part` and `PROMPT_SLOW` carry the whole start. The order tests were rewritten to
the new contract (ARCHITECTURE §Prompt assembly).

### AGORA-256: Gemini's cache
- **The plan:** `agents/gemini_cache.py`, a pure plan. A cache is made on the second answer with the same start,
  used while the history begins with its lines, renewed, and made again on a change, with a backoff after a failure.
- **The call:** `GeminiClient.reply` sends the start as the system instruction and the history, a separator and the
  tail as the message. It runs `caches.create/update/delete` and makes a plain retry on any failure.
- **The window:** `window_start` moves in steps (2 h).
- **Live check, made-up lines (≈ $0.07):** the first answer was plain, the second made the cache, and the third read
  **17,765 of 17,827** prompt tokens from it.
- **a477ec8, found before the deploy:** Устина's 12-hour window outgrew `HISTORY_N` 300 (324–333 lines), so its
  start slid by a line at every message. After such a slide the cache now holds the start alone for 2 h.

### AGORA-257: the other models
- **Claude:** the start goes to the system file on both the warm path and the cold one; the transcript, then the
  tail, is the message.
- **Sonnet API:** `cache_control` on the system.
- **OpenAI:** `prompt_cache_key`.
- **Codex:** the start as `model_instructions_file`.

### AGORA-258: the numbers
- **The cache's line:** `cache_usage_line` (kind `cache`).
- **The prices:** `PRICE_MODELS` takes 2–4 numbers; 3.1 Pro is `2/12/0.2/4.5`, in both examples and in the local
  `server/.env`.
- **The cost:** a cached read and a cache's storage are priced.
- **Analytics · Prompts:** «Read from the cache», by agent, model and kind, and the caches made.
