## Findings

### 1. 🟠 The period line only on its own line
`agents/recording.py` `_MARK_RE` (`^…$`, multiline).

**Failure scenario:** the model ends its answer «Зараз зберу тобі вечір. ЗАПИС: 2026-10-19 17:00 — 2026-10-19 19:00»
on one line. The pattern needs the line to start with the mark, so:
- the owner gets the raw line;
- no recording follows;
- nothing is logged.

A mark wrapped in a code fence leaves the fence behind in the words.

**Fix:** find the mark at the end of any line, after a space or punctuation, and take it out. Drop a fence that
becomes empty.

### 2. 🟡 The period line after the trim
`agents/herald.py` `answer` → `_think` trims to `ANSWER_MAX_CHARS` and cuts to the last full sentence. The mark has
no full stop, so in an answer over 1,500 characters it is cut off. The brief asks for one sentence plus the line, so
this is unlikely.

**Home:** backlog — read the mark before the trim (`_think` would take a hook).

### 3. 🟡 A page-bounded read counts as complete
`fetch_events` returns `True` after `MAX_PAGES × 2` pages (8,000 timeline events). A day holds a few hundred lines,
so this is only a guard. **Home:** backlog — say «the beginning is missing» in the counts line when the bound cuts.

### 4. 🟡 The stretch in memory
`record` keeps every piece's PCM (48 KB/s), and `assemble` builds a padded copy of each before joining a part. A
90-minute day would peak at about 0.6 GB; the host has 7.4 GB free.

**Home:** backlog — stream the PCM into a temp file per part if days grow.

### 5. 🟡 A failing spawned task is quiet
`Herald._spawn` adds no done-callback. An unexpected exception in `answer`/`record` (outside the handled failures) is
logged only by asyncio's "Task exception was never retrieved" when the task is collected. The owner may have heard
«Зараз зберу…» and then gets nothing. The pattern is older than v5.4 (the digest and the answer since v5.1).

**Home:** backlog — a done-callback that logs the exception's type.

### 6. 🟡 Re-voicing on every request
Each recording speaks the owner's typed lines and members' text-only lines again (49 TTS calls in the 25-minute
recording). The budget guards it. **Home:** backlog — a per-day cache of the spoken PCM, if repeats become common.

## Fixes applied

### #1 — the period mark anywhere · 75d604c
- **Change:** `_MARK_RE` finds the mark anywhere — on its own line, after his sentence, in stars, quotes or a code
  fence.
  - The last mark gives the period.
  - Every mark is taken out of his words.
  - A fence the mark leaves empty is dropped.
- **Regression test:** `test_the_period_line_after_his_sentence_or_in_a_fence_is_read_too` covers three forms (the
  same line, a fence, inline code). It fails on the old pattern.
- **Verification:** lint ✓ · tests ✓ (full suite).

**Architecture impact:** none. ARCHITECTURE already says his answer «ends with» the line; the code now also reads
it when it shares a line with his words.

## What's solid

- **Live speed and edges.** Measured with ffmpeg 7.1 in Hermes's container, the pipeline (decode, `loudnorm`,
  pauses, Opus) keeps time and speech edges exactly (2.0 s in → 2.0 s out, edges within 50 ms).
- **The real cause was found, not guessed.** The cut phrases came from the v5.2 download. Declared lengths now match
  downloaded ones live, and the regression test streams in chunks like aiohttp.
- **The marker never leaves.** The period line is never sent, never logged, and validated: parsed, its end no later
  than now, at most 25 h. The DST day is pinned.
- **The budget is Hermes's own:** the speakers' budget is untouched, and every TTS call is a `tts` usage line.
- **No archive:** the room is read on demand, and only the sent file remains.
- **Logs** carry counts and minutes, never a word or a sound.
- **The plan is pure**, tested on plain data:
  - each line kind;
  - the 30 s voice and text pairing;
  - purrs, edits, transcripts and strangers left out.
