# v4.7 — Issues

Issues for phase **v4.7 — Agent settings and Claude's files in the panel** (version **v4 — Ensemble**), derived from
the Tasks and DoD in [ROADMAP.md](../ROADMAP.md) §v4.7 and the contracts in [ARCHITECTURE.md](../ARCHITECTURE.md).
This file covers one phase; ids continue from the previous phase (AGORA-072 → **AGORA-073…077**).

The panel stops being only a viewer of the room's settings. Every non-secret agent setting is listed by a schema in
code. The owner overrides a setting in the panel; the override is kept in `state/settings.json`, applied by each
agent at its start over the environment, and made effective by restarting exactly the agents it concerns. Claude's
own folder becomes reachable from his card: list, read, download, upload, delete.

**Owner decisions** (2026-10-11, at the phase start):
- the overrides file `state/settings.json`, written only by the panel;
- a change applies by a restart;
- every file operation on Claude's folder.

**Reconciled with the code:**
- **Settings in the code:**
  - the agents read about 40 settings with `os.environ.get(NAME, default)` in `agents/agent.py`, plus
    `weights_from` for the persona weights;
  - `MEMORY_DAYS`, `MEMORY_WEEKS` and `MEMORY_MONTHS` go through a local `env()`;
  - the Gemini model is a constant in `agents/llm.py`.
- **The panel:**
  - it already mounts `state/` read-write and restarts a service through `Supervisor.act`;
  - its registry loads each agent's type, engine and capabilities through `agents/roster.py`, so it can import the
    pure `agents/` modules.
- **Settings shared across services:** compose interpolates the shared turn settings into Claude's service; every
  agent reads `state/` at `/app/state`.

## v4.7 — Agent settings and Claude's files in the panel

### AGORA-073 — The settings schema, the overrides file and their resolution at an agent's start

**Description:**
A pure schema in `agents/settings.py` lists every tunable setting. `state/settings.json` holds the panel's overrides.
At its start an agent (`agents/agent.py` `main`) applies the valid overrides over its environment and writes what it
runs with to `state/<name>.settings.json`. The Gemini model becomes the setting `GEMINI_MODEL` (`agents/llm.py`).

**What needs to be done:**
- **`SCHEMA`** holds one `Setting` per tunable: `name`, `kind` (`int` / `float` / `hours` / `choice` / `text`), the
  bounds or choices, the code default (the same as the agent's own default), a unit, a one-line Ukrainian
  description, a group, and a `scope`. The scope is `shared` (every agent: the turn settings, including `CAT_REACT_P`
  and `CAT_PURR_P`, which every agent uses for the owner's reserved answers) or a selector on the roster: a type
  (`persona`), a capability (`nudge`, `news`) or an engine (`claude-sdk`, `gemini`).
- **The settings it covers:**
  - **room & turns:** `HISTORY_N`, `REPLY_MAX_TOKENS`, `MAX_BOT_TURNS`, `OWNER_REPLIERS`, `FALLBACK_S`,
    `BOT_REPLY_P`, `REPLY_DELAY_S`, `BOT_WINDOW_S`, `CAT_REACT_P`, `CAT_PURR_P`;
  - **personas:** `PERSONA_ASK_P`, `PERSONA_DISAGREE_P`, `PERSONA_PLAN_P`, `PERSONA_STORY_P`, `LOCATION`;
  - **memory:** `MEMORY_DAYS`, `MEMORY_WEEKS`, `MEMORY_MONTHS`, `SESSION_IDLE_S`, `SESSION_MAX_MESSAGES`,
    `SUMMARY_MAX_WORDS`, `PLAN_MAX_WORDS`, `PLAN_MUTATION_RATE`;
  - **the cat:** `CAT_MAX_WORDS`, `CAT_MEMORY_P`, `CAT_NUDGE_IDLE_S`, `CAT_NUDGES_PER_DAY`, `CAT_NUDGE_HOURS`;
  - **Claude:** `CLAUDE_MODEL`, `CLAUDE_HISTORY_N`, `CLAUDE_TIMEOUT_S`, `CLAUDE_CODE_MAX_OUTPUT_TOKENS`,
    `CLAUDE_NEWS_EVERY_S`, `CLAUDE_NEWS_IDLE_S`, `CLAUDE_NEWS_PER_DAY`, `CLAUDE_NEWS_HOURS`;
  - **Gemini:** `GEMINI_MODEL` (choices; `gemini-2.5-flash` by default).
- **What it never covers:** secrets (`*_PASSWORD`, `*_TOKEN`, `*_KEY`), the room and owner ids, `TIMEZONE`, paths,
  the `ANTHROPIC_*` / `CLAUDE_CODE_USE_*` family, or any forbidden name. A test fails if one appears.
- **Pure functions:**
  - `validate(name, raw) -> value | error`;
  - `load_overrides(path)`: a missing or corrupt file means no overrides;
  - `save_overrides(path, mapping)`: atomic, 0600;
  - `concerns(setting, member) -> bool`;
  - `apply_overrides(env, overrides, member) -> (applied names, ignored names)`: only the schema's names that
    concern this member, valid values only; an unknown or invalid one is ignored and logged by name;
  - `effective(env, member, overrides) -> {name: {"value", "source"}}`, where the source is `default` / `env` /
    `panel`.
- **At start** (`main`, after the config and before `Agent(cfg)`):
  - apply the overrides from `state/settings.json`;
  - log `settings: overridden <names>` (names only);
  - write `state/<name>.settings.json` (atomic, 0600, only the schema's names: no secret can be in it).
- **`GEMINI_MODEL`:** `GeminiClient` reads the model from the environment at construction, the default unchanged;
  the usage line keeps the model it called.
- **ARCHITECTURE:**
  - the state files `settings.json` and `<name>.settings.json`;
  - the resolution order, code default < env < panel;
  - the env table gains a «tunable in the panel» note and `GEMINI_MODEL`;
  - §The panel's «there is no settings view» becomes «non-secret settings only».

**Dependencies:** None

**Expected result:**
An override in `state/settings.json` changes what an agent runs with at its next start, and each agent tells the
panel what it runs with.

**Acceptance criteria:**
- [ ] The schema's defaults equal the code defaults, pinned by a test that compares each setting against the
  agent's own reading with an empty environment.
- [ ] No secret, forbidden or id name is in the schema.
- [ ] The resolution order is code default < env < panel. An invalid or unknown override is ignored and logged by
  name, and an override that does not concern the member is not applied.
- [ ] `state/settings.json` and `state/<name>.settings.json` are written atomically with mode 0600, and a corrupt
  file means no overrides.
- [ ] An agent started with an override runs with it, for example `MAX_BOT_TURNS` and `CAT_NUDGE_IDLE_S`.
- [ ] **Tests:** `tests/test_settings.py` covers the schema, validation, the resolution, scoping and the files;
  an agent-level test covers the start-time override; `GEMINI_MODEL` is tested in `tests/test_usage.py`. Gemini is
  mocked.
- [ ] **Contract:** the state files, the resolution order and `GEMINI_MODEL`, with ARCHITECTURE and the pinning
  tests updated.
- [ ] **Gates:** lint, tests.

### AGORA-074 — The settings API: read the schema and the effective values, save overrides, restart who they concern

**Description:**
`panel/settings.py` and two routes in `panel/app.py`. `GET /api/settings` returns the schema with each setting's
override and effective values. `PUT /api/settings` validates and saves the overrides, then restarts exactly the
agents they concern through `Supervisor.act`.

**What needs to be done:**
- **`GET /api/settings`** returns the schema (grouped, with defaults, units and descriptions), the current override
  of each setting, and per agent the effective value and its source from `state/<name>.settings.json`. An unreadable
  agent file degrades to `null` for that agent and never causes a 500.
- **`PUT /api/settings`** takes `{"set": {name: value}, "reset": [names]}`:
  - every name must be in the schema (an unknown one is a 422) and every value valid (otherwise a 422 naming the
    setting);
  - it writes the merged overrides atomically;
  - it computes the agents concerned from the registry (type, capabilities, engine) — every agent for a `shared`
    setting;
  - it restarts them one by one through `Supervisor.act(name, "restart")`, and a stopped agent is not started;
  - it answers with `{"saved": [...], "restarted": [...], "skipped": [...]}`.
- **Safety:**
  - Bearer auth as everywhere;
  - names resolve only through the schema, values only through `validate`;
  - nothing from the request reaches a path, an argv or the docker API except a registry agent name.
- **ARCHITECTURE:** the panel API surface gains the two routes, which reverses the v3.4 «exactly three POST routes»
  note; `tests/test_panel_api.py` pins them.

**Dependencies:** AGORA-073

**Expected result:**
The owner's change is saved and takes effect with one restart of the agents it concerns.

**Acceptance criteria:**
- [ ] A 401 comes back without the token, and a 422 for an unknown name or an invalid value, with nothing written.
- [ ] A `shared` setting restarts every agent. `CAT_NUDGE_IDLE_S` restarts only the cat, `CLAUDE_TIMEOUT_S` only
  Claude, and `PERSONA_ASK_P` only Ada and Bruno.
- [ ] A reset drops the override. A stopped agent is skipped, never started.
- [ ] The GET shows the default, the override and each agent's effective value with its source. A broken agent
  file never causes a 500.
- [ ] **Tests:** `tests/test_panel_settings.py` with the fake supervisor and registry, covering the routes, the
  validation, the restart sets, the file and auth.
- [ ] **Contract:** the panel API surface, pinned in `tests/test_panel_api.py`, with ARCHITECTURE §The panel
  updated.
- [ ] **Gates:** lint, tests.

### AGORA-076 — Claude's files: the folder in the panel — list, read, download, upload, delete

**Description:**
`panel/files.py` and routes in `panel/app.py`; the compose mount of `../claude-workspace` into the panel; a Files
tab on Claude's card (`panel/static/app.js`).

**What needs to be done:**
- **Compose:** the panel mounts `../claude-workspace` at `/claude-workspace`, read-write, as uid 1000, the same as
  Claude.
- **Routes, only for an agent with the `claude-sdk` engine in the registry:**
  - `GET /api/agents/{name}/files`: the files, recursive, with relative path, size and time;
  - `GET /api/agents/{name}/files/{path}`: a text file's content, capped at 256 KB (a binary file is
    download-only), or `?download=1` as an attachment;
  - `PUT /api/agents/{name}/files/{path}`: the raw body; ≤ 5 MB; `?overwrite=1` is needed to replace a file;
    missing folders are created;
  - `DELETE /api/agents/{name}/files/{path}`.
- **The path guard:**
  - relative only, no `..`, no leading `/` or `~`, no NUL, no surrounding whitespace;
  - resolved with `realpath` inside the folder, so a symlink out is refused;
  - no hidden names (`.`-prefixed).
- **Safety and logging:** Bearer auth; the log names the action and path only, never the content.
- **The Files tab** on Claude's card: the list; open a text file; download; upload with a file picker (overwriting
  asks for a confirmation); delete (asks for a confirmation).
- **ARCHITECTURE:**
  - the panel API (the files routes);
  - the compose mount;
  - the security note: his folder is the only one the panel's file routes reach, and what the owner uploads is a
    file Claude may read with his tools.

**Dependencies:** None

**Expected result:**
The owner sees Claude's notes, downloads them and gives him files to read.

**Acceptance criteria:**
- [ ] List, read, download, upload and delete work inside the folder. An overwrite needs the flag, and the caps
  hold.
- [ ] The following are refused, with nothing touched: `..`, an absolute path, `~`, a hidden name, a symlink out,
  an agent without the engine, a missing token.
- [ ] **Tests:** `tests/test_panel_files.py` on a temporary folder, covering every route, the guard table, the caps
  and auth. The compose test pins the mount. Static checks cover the tab and its confirmations.
- [ ] **Contract:** the panel API and the compose panel volumes, with ARCHITECTURE updated.
- [ ] **Gates:** lint, tests, compose.
