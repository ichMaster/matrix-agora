## Findings

### 1. 🟠 The panel's action events never reach its log
`panel/actions.py` logs every action to `panel.actions`, but nothing configures logging in the panel process:
uvicorn sets up only its own loggers, the root logger stays at WARNING with no handler, and every `log.info("action
…")` is dropped. Seen live: after a full run of stops, starts, a restart, a homeserver stop and a forget,
`docker compose logs panel | grep panel.actions` was empty. ARCHITECTURE promises each action is logged as an event.
**Fix:** `create_app` gives the `panel` logger its own console handler at INFO (not the root's — no global side
effects), so `docker logs panel` carries `action stop ada → stopped in 2.6s`.

### 2. 🟡 A failed `compose up` is logged without the reason
`ComposeRunner.up` raises `502 compose up <service> failed` and drops compose's stderr — with #1 fixed the log says
*that* it failed, never *why*.
**Fix:** log the last stderr line (truncated); compose's errors name files and services, not values.

### 3. 🟡 Library noise buries the agents' events
The agents' log — tailed by the panel — carries a google-genai line on every Gemini call ("AFC is enabled…", and a
WARNING "Direct use of automatic function calling…") and a nio INFO line per room event. Live: 29 + 5 lines of the
former in Ada's 587-line log, plus the nio lines.
**Fix:** turn automatic function calling off in the request config (the agents pass no tools), and set the `nio`
loggers to WARNING in `setup_logging`.

### 4. 🟡 Two compose versions
The deploy runs the host's compose (v5.6); a panel start runs v2.39.4. If they hash a service's config differently, a
panel start recreates a container the deploy created — harmless (it was stopped anyway) but surprising.
**Defer → backlog:** pin one compose version in both places.

### 5. 🟡 The panel image grew ~150 MB
The CLI binaries are the price of creating a missing container with the real compose project.
**Defer → backlog.**
