the Tasks and DoD in [ROADMAP.md](../ROADMAP.md) §v4.1, the design in

[ARCHITECTURE.md](../ARCHITECTURE.md). This file covers one phase; ids continue from the previous phase
(AGORA-043 → **AGORA-044…048**).

bounded number of answers whatever the number of agents. It is still only Ada and Bruno, so their memories, plans,
today block and summaries work exactly as before. Ada and Bruno are `persona` agents on the `gemini` engine; the
other types and engines (`creature`, `assistant`, `bridge`; `claude-sdk`, `lumi-http`) arrive with their own phases
(v4.2, v4.4, v4.6).

### AGORA-044 — The roster and agent types with capabilities

**Description:**
Replace the hard-coded pair with a **roster** read from the registry, and give every agent a `type` that sets its
capabilities. Touches `agents/roster.py` (new), `agents/config.py`, `agents/agent.py`, `agents/logic.py`,
`agents/turns.py`, `agents/ada.toml`, `agents/bruno.toml`, `scripts/run-agent.sh`, ARCHITECTURE.md, tests.

**What needs to be done:**
- **TOML schema.** Each agent TOML gains:
  - `type` (`persona` only in this phase; unknown types refuse to start with a clear error);
  - `engine` (`gemini` only in this phase);
  - `name_forms`: the lowercase forms that address the agent (Ada: `ада ади аді аду адою адо`; Bruno: `бруно`). These move out of `NAME_FORMS` in [agents/turns.py](../../agents/turns.py#L16);
  - `[capabilities]`: overrides of the type's defaults. The keys are `canon`, `life`, `summary`, `chronicle` (day memories + digests), `plans`, `today`, `world`. A `persona` has them all on;
  - `[turns]`: `mode` (`ranked` | `ambient` | `mention-only`; Ada and Bruno: `ranked`) and `weight` (default `1.0`).
- **`agents/roster.py`** — pure loading, no network:
  - `Member(localpart, user_id, name, name_forms, type, engine, capabilities, mode, weight, panel)`;
  - `load_roster(sim_id, registry_path, agents_dir) -> dict[localpart, Member]`: the simulation's `agents` list from `simulations.toml`, then each listed TOML.
  - It is the one parser used by both the agents and (AGORA-047) the panel.
- **`agents/config.py`.** `canon` and `life` become required only when the type's capabilities need them. For a persona, the current checks stay exactly as they are.
- **`agents/agent.py`:**
  - The roster replaces `OTHER` ([agent.py:87](../../agents/agent.py#L87)) and the hard-coded display names ([agent.py:106-108](../../agents/agent.py#L106-L108)).
  - `self.names` maps every member's `user_id` to its `name`, plus `OWNER` → `Ich`. It feeds the transcript, `seed_context`, `clean_reply`'s other names and the session timeline.
  - Gate by capability, all on for personas, so nothing changes for Ada and Bruno:
    - `build_prompt` sections;
    - `ensure_today` before a reply;
    - `ensure_plans`;
    - the chronicle in `world_tick` (day memories, digests);
    - `summarize`, the journal and the shutdown summary;
    - the startup kick in `run()`.
- **`agents/logic.py`.** `should_handle` takes the set of other members' `user_id`s. The allowlist becomes `{OWNER} ∪ roster − own user_id`. Everything else stays: `ROOM_ID` only, `RoomMessageText` only, the rest logged as `ignored`.
- **`agents/turns.py`.** `mentions(text, forms, user_id)` takes the forms from the roster.
- **`scripts/run-agent.sh`** accepts any agent listed in the registry (via `agents.roster`), not just `ada|bruno`.
- **ARCHITECTURE.md:**
  - §Contracts: the agent TOML schema; the message filter and allowlist rule;
  - §Message flow (the allowlist);
  - §Canon (`name_forms` in the TOML).

**Dependencies:** None

**Expected result:**
Ada and Bruno behave exactly as before, but nothing in the code names them: the room's members come from the registry.

**Acceptance criteria:**
- [ ] `load_roster` returns both members with their names, forms, type, engine, capabilities, mode and weight. A missing TOML, an unknown `type` or `engine`, or a bad `mode` refuses to start with a clear error.
- [ ] `OTHER`, the hard-coded names and `NAME_FORMS` are gone (a grep finds no `"Ада" if "ada"`-style mapping).
- [ ] The allowlist accepts the owner and every other roster member, and logs `ignored` for anyone else.
- [ ] Capability gating: with a capability switched off in a test TOML, the matching call is never made. With the persona defaults, every call happens as before.
- [ ] **Tests:**

  - `tests/test_config.py`: the schema;

### AGORA-045 — Turn-taking for N agents: rank, R1–R4, modes, fallback

**Description:**
Rewrite the who-replies rules so that a message has a small, bounded number of answers for any number of agents,
with no coordination. Touches `agents/turns.py`, `agents/agent.py`, `.env.example`, `server/.env.example`,
ARCHITECTURE.md, tests.

**What needs to be done:**
- **`rank(event_id, members) -> list[localpart]`.** Weighted rendezvous hashing:
  - `u = (int.from_bytes(sha256(f"{event_id}\n{localpart}").digest()[:8]) + 1) / 2**64`, `score = -weight / ln(u)`, highest first;
  - `hashlib` only, **never** Python's `hash()`.
- **R1, the owner's message:**
  - **names agents** (any form or the Matrix id): exactly the named ones answer;
  - **a group address** («всі», «усі», «всім», «усім», «кожен», «кожна», «кожному», «ви всі»; a pure `addresses_everyone(text)`): every `ranked` member answers;
  - **otherwise:** the top `OWNER_REPLIERS` (new env var, default 2) of `rank(event_id, ranked members)` answer, after the usual 1–`REPLY_DELAY_S` delay;
  - answers to the owner are never stopped by the limit, but they count toward it.
- **R2, an agent's message M:**
  - at most **one** candidate among the `ranked` members other than the sender: the named ones, top by rank; otherwise the top of `rank(M.event_id, …)`;
  - the candidate replies if `wave_count(M) < MAX_BOT_TURNS` and a roll passes `BOT_REPLY_P`;
  - **naming decides who, not whether**: the probability gate applies to a named candidate too.
- **`wave_count(timeline, owner, now_ms, window_ms)`.** Agent messages since the owner's last message, within `BOT_WINDOW_S`, **including** M. It replaces `bot_streak`, whose count excluded M.
  - `MAX_BOT_TURNS` new = old + 1 for the same behavior, so the default becomes 3 (= today's 2). The `.env` examples change to `3`.
- **R3, the re-check at fire time** (agent-to-agent replies only). Before the model call and again before sending (the Gemini engine): M is still the latest message in the timeline, and `wave_count` is still below the limit. Otherwise drop, and log `silent: moved on`.
- **R4, the rate.** A candidate blocked by the limit pauses until the window frees, then re-evaluates (M still latest, count, roll). This keeps today's `pause_until_window_frees` / `resume_later` semantics.
- **Modes:**
  - `ranked` takes part in R1 and R2;
  - `mention-only` answers only when named (or on a group address);
  - `ambient` is accepted by the schema but unused until v4.2.
- **The fallback.** If no agent has answered the owner within `FALLBACK_S` (new env var, default 30), the best-ranked `ranked` member that was **not** chosen answers.
  - It is derived from the timeline: each agent schedules its own check, with no coordination.
  - With two agents and `OWNER_REPLIERS=2` it never fires.
- **`agents/agent.py`:**
  - timeline entries become `(name, ts_ms, event_id)`;
  - the decision gets the trigger's `event_id`;
  - `reply_later` carries the trigger for R3.
- **Unchanged:** `PASS`, the delays, the one-pending-reply coalescing, and "background waves stay a rate, not a lock" (owner, 2026-10-10).
- **ARCHITECTURE.md:**
  - §Turn-taking rewritten (R1–R4, `rank`, the group address, `wave_count`, modes, the fallback);
  - §Configuration (`OWNER_REPLIERS`, `FALLBACK_S`; the new meaning of `MAX_BOT_TURNS` and its default 3);
  - §Contracts (the turn-taking semantics; the env var names).

**Dependencies:** AGORA-044

**Expected result:**
An owner message without names gets exactly `OWNER_REPLIERS` answers. A named one gets only the named agents. An
agent message has at most one next speaker. A wave never exceeds `MAX_BOT_TURNS` agent messages beyond the answers to
the owner.

**Acceptance criteria:**
- [ ] `rank` is deterministic. A subprocess with a different `PYTHONHASHSEED` gets the same order. Over many ids, a member's share of first places follows its weight. Roster order does not matter.
- [ ] R1: named → exactly the named; a group address → every ranked member; unnamed → exactly `OWNER_REPLIERS`, and every agent computes the same set.
- [ ] R2: one candidate, never the sender; names restrict the candidates; the probability gate applies when named.
- [ ] R3 drops a reply when a newer message arrived before the call or before sending. R4 resumes only when nothing newer arrived.
- [ ] `wave_count` includes M, honours the window, and resets on an owner message. The migration equivalence (new = old + 1) is pinned by a test.
- [ ] The fallback answers after `FALLBACK_S` only when nobody did, and only from the top unchosen member.
- [ ] **Tests:**
  - `tests/test_turns.py` rewritten for the pure functions;
  - a scripted **multi-agent simulation** (four fake members, rng and clock injected): a wave never exceeds `MAX_BOT_TURNS` beyond the answers to the owner;
  - `tests/test_first_sync.py` agent-level flows (R3 and R4 with the mocked nio client).
- [ ] **Contract:** turn-taking semantics and the env var names (`OWNER_REPLIERS`, `FALLBACK_S`, the `MAX_BOT_TURNS` meaning) are in ARCHITECTURE.md §Turn-taking, §Configuration and §Contracts, and in both `.env` examples. They are pinned by `tests/test_turns.py` and the env-name parity in `tests/test_compose.py`.
- [ ] **Gates:** lint, tests, compose (the examples changed).

### AGORA-046 — The `Responder` interface and reply length

**Description:**
Put the reply engine behind one interface, so later engines (Claude, Lumi) plug in. Make replies chat-sized and
never cut mid-sentence. Touches `agents/responder.py` (new), `agents/llm.py`, `agents/agent.py`,
`agents/canon/common.md`, `.env.example`, `server/.env.example`, ARCHITECTURE.md, tests.

**What needs to be done:**
- **`agents/responder.py`:**
  - `Turn(lines, instruction, max_tokens, kind)`;
  - `Reply(text, finish, usage)`, where `finish` is `"stop"` or `"max_tokens"`;
  - `Responder` protocol with `async respond(turn) -> Reply | None`.
- **`GeminiResponder`** wraps `GeminiClient` and keeps today's contract exactly: the system instruction in the ARCHITECTURE §Prompt assembly order, the `"Name: text"` lines, usage accounting unchanged. `GeminiClient.generate` additionally reports the finish reason (`MAX_TOKENS` → `"max_tokens"`).
- **`Agent.reply`** calls the responder. The engine is chosen by the TOML's `engine` (`gemini` only in this phase).
- **Reply length:**
  - `REPLY_MAX_TOKENS` (new env var, default 200) replaces the hard-coded `max_output_tokens=400` for replies ([agents/llm.py:38](../../agents/llm.py#L38)). Summaries, memories and plans keep their own caps.
  - A pure `trim_to_sentence(text)`: when `finish == "max_tokens"`, cut to the last complete sentence (`.`, `!`, `?`, `…`). If none is left, stay silent and log `silent: cut mid-sentence`.
  - `agents/canon/common.md` gains «Пиши 1–3 речення; довше — лише коли тебе прямо попросили розповісти» ("Write 1–3 sentences; longer only when someone explicitly asks you to tell more").
  - The human-belief canon scan must still pass.
- **`HISTORY_N` default 40** (owner, 2026-10-10), in the code and both `.env` examples.
- **ARCHITECTURE.md:**
  - §Configuration (`REPLY_MAX_TOKENS`, `HISTORY_N` 40);
  - §Prompt assembly / reply cleaning (sentence trimming after a cap);
  - §Components (the responder seam).

**Dependencies:** AGORA-044

**Expected result:**
Replies go through one engine interface. They are short by instruction and by cap, and never end mid-sentence.

**Acceptance criteria:**
- [ ] With a mocked Gemini, `GeminiResponder` produces the same instruction, transcript and usage line as before.
- [ ] A `MAX_TOKENS` reply is trimmed to its last complete sentence; one with no complete sentence is silence.
- [ ] `REPLY_MAX_TOKENS` reaches the reply call; other kinds keep their caps.
- [ ] **Tests:**
  - `tests/test_responder.py` (new): the protocol, finish-reason mapping, `trim_to_sentence`;
  - `tests/test_logic.py`: the canon scan with the new `common.md` line;
  - `tests/test_first_sync.py`: reply path through the responder;
  - Gemini mocked; no network.
- [ ] **Contract:** the env var names (`REPLY_MAX_TOKENS`; the `HISTORY_N` default) are in ARCHITECTURE.md §Configuration and §Contracts and in both `.env` examples, pinned by the env-name parity in `tests/test_compose.py`.
- [ ] **Gates:** lint, tests, compose (the examples changed).
