## Findings

### 1. 🟠 Writing first swallows an owner message
`Agent.maybe_private_nudge` sets `_private_pending` while composing. `on_private` then sees a pending answer, sets
`_private_again` and returns, but no loop reads that flag afterwards.

**Failure scenario:** at 18:00 she writes first. While the line is being composed (a few seconds), the owner writes
«привіт!». It is logged as coalesced, and nothing answers it.

**Fix:** when writing first ends with `_private_again` set, the answer path starts (`private_later(0)`).

### 2. 🟠 A stale private room locks the chat
`should_join_invite` accepts one private room: the stored one, or none.

**Failure scenario:** the owner leaves or deletes the direct chat in Element and starts a new one with `@kira`. The
invite to the new room is refused, because a room is stored. She stays in the old room, which the owner no longer
sees, and the private chat can't be reopened.

**Fix:** the stored room counts only while the owner is still in it, like Hermes's `needs_private_room`. When he
isn't, a new invite of his is accepted, replaces the stored room, and the old one is left.

### 3. 🟡 No duplicate check in the private chat
**Home:** backlog.

### 4. 🟡 One summary for both rooms
One memory is the owner's decision, and the summary labels private lines «наодинці». Whether she keeps quiet in
Agora is part of the owner's DoD, waived for now. **Home:** backlog, revisited if she lets something slip.
