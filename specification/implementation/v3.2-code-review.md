## Findings

### 1. 🟠 Python is PID 1 in the containers: SIGTERM is ignored until a handler exists
`server/docker-compose.yml` — the image's entrypoint makes `python` PID 1, and the kernel never applies the
default action of SIGTERM to PID 1. `usage-report` installs no handler, so **every** `docker compose stop`
(and every deploy that recreates it) waits the full grace period and ends in SIGKILL — measured on the host:
10 s, exit 137. The agents install their handler only after login, backfill and the startup kick; a stop or
redeploy during that window waits 30 s and is killed. Nothing reaps zombies either.
**Fix:** `init: true` on the three services (Docker's tini as PID 1 forwards signals and reaps); the agents'
own handler still turns SIGTERM into the session summary.

### 2. 🟡 The server runs `:edge` until someone switches it to a release
AGORA-032 deployed with `AGENT_IMAGE_TAG=edge`, so the next deploy picks up whatever `main` last built — docs
commits included — not a release.
**Fix (at release):** once `v3.2.0` publishes `:latest`, set `AGENT_IMAGE_TAG=latest` in `server/.env` and
redeploy.

### 3. 🟡 `REGISTRATION_TOKEN` reaches the agent containers through the shared env file
`env_file: .env` hands the agents every variable in `server/.env`, including the (now unused — registration is
closed) registration token. Nothing logs the environment, so this is exposure, not a leak.
**Defer → backlog:** a separate `agents.env`, or blank it in the agents' `environment`.

### 4. 🟡 The single-instance lock is per host
`flock` cannot see the other machine: a dev-mode Ada on the Mac and the server's Ada would both reply. The
docs say "never at the same time"; nothing enforces it.
**Defer → v3.3:** the panel shows where each agent runs and can stop one before the other starts.

### 5. 🟡 The Mac `state/` is now a stale fork
After the migration the server's `state/` is the live one; a later dev run on the Mac starts from older
memories and writes summaries the server never sees.
**Defer → backlog:** a `--pull-state` step for dev mode, or a note in the dev-mode docs.

## What's solid

- No secrets in the image: `.dockerignore` and the Dockerfile's `COPY` set are pinned by tests; the built image
  was inspected — no `.env`, no `server_con.yaml`, empty `state/`.
- On the host `server/.env` is 0600 and `state/` is 0700, owned by the host user; the containers run as
  `1000:1000`, so nothing becomes root-owned.
- The migration kept the Matrix sessions: both agents restored their devices — no new devices.
- `docker stop -t 30 ada` writes the summary and exits 0 in 3 s; the lock refuses a second instance.
- CI uses only `GITHUB_TOKEN`, pushes only on `push` events, and pins its gates and tags in a test.
- The daily-report sleep uses real seconds, so the DST switch on 2026-10-25 doesn't shift it.

## Fixes applied

- **#1 — `5eeb2bb`:** `init: true` on `ada`, `bruno` and `usage-report` — Docker's init (tini) is PID 1, forwards
  SIGTERM and reaps. Regression test: `test_python_is_never_pid_1` in `tests/test_compose.py` (fails without
  the fix). Verified live after a deploy: `docker top` shows `/sbin/docker-init -- python …`; `usage-report`
  stops in 1 s (exit 143, terminated by SIGTERM) instead of 10 s + SIGKILL (exit 137); `bruno` stops at once with
  `stopping — writing the session summary` → `stopped`, exit 0.

**Verification:** `uv run ruff check .` ✓ · `uv run pytest` ✓ (178) · compose ✓.
