## Findings

### 1. 🟠 The backup's part missing from the ⚙️ line — `agents/private.py` `silence_line`

The decline branch returns «відмова claude (…)» and skips v5.22 review #5's suffixes; on Claude a decline is the main
way into the backup, so «відмова claude (stop · bio)» with NovelAI silent never says the backup did not answer.
**Fix:** the decline's words, then the same suffixes.

### 2. 🟠 A plain-text decline kept as her memory — `agents/agent.py` `_talk_text`, `agents/claude_sdk.py` `think`

`_judge` checks `refusal_marker` only for answers; a summary Haiku declines in its text is kept and reaches her prompt
as what she remembers (on Gemini the talk check caught it). **Fix:** `_talk_text` treats a `refusal_marker` in the
summary as a decline (`LAST_BLOCK` refusal, None) — the stricter tries then the empty end take it.

### 3. 🟠 A declined session summary loops — `agents/agent.py` `summarize`

v5.22's second try on 3.1 Pro runs only for a thinking reply model; on Claude a declined summary fails and is tried
on every event while the session is full; `extract_facts` waits for a summary. **Fix:** on a decline, write it once more
from the session without her private lines (they are what Claude declines; her talk summaries keep them), and no new
try until a new line.

### 4. 🟡 The fallback's block labelled Claude — `silence_line`'s `main`

**Fix:** the ⚙️ line names the engine that served (`by` `gemini` → «gemini»).

### 5. 🟡 Commands logged as unknown — `telegram_command`

**Fix:** the log's name taken before `/claude` is mapped to the main model.

### 6. 🟡 A decline never tried twice — DEFER → the owner

A Claude classifier's false positive closes his lines at once. Gemini's answer-stage blocks were tried once more
(AGORA-213, the owner's decision); whether a decline is, is the owner's call — carried into the release notes.
