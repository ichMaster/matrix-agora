### AGORA-045: Turn-taking for N agents: rank, R1–R4, modes, fallback
**Status:** completed · **Commit:** 61706e4 · **GitHub:** #45
**Gates:** [x] lint · [x] tests · [x] compose
- **`rank`** is weighted rendezvous hashing over `sha256(event_id + localpart)`. The same order holds in a subprocess with another `PYTHONHASHSEED`, and first places follow the weights.
- **R1** handles named agents, the group address («всі», «кожен»…) and the top `OWNER_REPLIERS`.
- **R2:**
  - at most one next speaker per agent message;
  - naming decides who, not whether.
- **The wave** (`wave_count`) includes the answered message (`MAX_BOT_TURNS` new = old + 1, default 3).
- **R3** re-checks before the model call and before sending; a newer trigger coalesces into the pending reply.
- **R4** keeps the rate.
- **The fallback** fires after `FALLBACK_S`.
- **Found by the 4-agent simulation, fixed in the same commit:**
  - **The bug:** with «всі» and four agents, a follow-up could overtake answers to the owner that were still on their way, so the wave reached 5.
  - **The fix:** `pending_answers` reserves R1's chosen answers in the wave. Every agent computes them from the owner's latest message, so no coordination is needed.
