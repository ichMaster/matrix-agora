# v3.3 — Issues

Issues for phase **v3.3 — The panel: viewing (read-only)** (version **v3 — Operations**), derived from the
Tasks and DoD in [ROADMAP.md](../ROADMAP.md) §v3.3, the contracts in [ARCHITECTURE.md](../ARCHITECTURE.md) and
the UI handoff in [design/design_handoff_agora_panel/](../design/design_handoff_agora_panel/README.md) with the
owner's adoption notes in [design/README.md](../design/README.md). This file covers one phase; ids continue
from the previous phase (AGORA-032 → **AGORA-033…038**).

The panel shows everything and changes nothing: a FastAPI app with a read-only JSON API behind
`PANEL_TOKEN`, built on a simulation registry with one entry (`agora`), and one static English page to the
Claude Design handoff — the simulation, both agents (state, logs, memory, plans, today, tokens) and the host.
It runs as the `panel` container beside the stack. Start/stop/restart and forget are v3.4.

## v3.3 — The panel: viewing (read-only)

### AGORA-033 — Simulation registry + the panel skeleton: auth, registry routes

**Description:**
The simulation registry (one `agora` entry) that both the agents and the panel resolve through, the agents'
TOML `simulation` key, and the FastAPI skeleton with the Bearer gate. Touches `simulations.toml`,
`agents/config.py`, `agents/ada.toml`, `agents/bruno.toml`, `agents/Dockerfile`, `panel/__init__.py`,
`panel/app.py`, `panel/registry.py`, `pyproject.toml` (a `panel` dependency group), ARCHITECTURE, tests.

**What needs to be done:**
- `simulations.toml` (repo root, committed): `[agora]` — `kind = "matrix-chat"`, `title = "Agora"`,
  `description = "private Matrix room · agora.lan"`, `services = ["homeserver"]`,
  `health = { service = "homeserver", path = "/_matrix/client/versions" }`,
  `endpoints = { homeserver = "HOMESERVER", room = "ROOM_ID" }` (the env names the entry's agents connect
  with), `agents = ["ada", "bruno"]`.
- `agents/<name>.toml` gains `simulation = "agora"`; `load_config` resolves it in the registry (unknown →
  `ConfigError`) and reads `HOMESERVER` / `ROOM_ID` through the entry's `endpoints`. The agent image copies
  `simulations.toml`.
- `panel/registry.py`: load + validate the registry; `simulation(id)`, `agent(name)`, `service(sim, name)`
  return `None` for anything not listed — the only way request data turns into a name.
- `panel/app.py`: FastAPI; every `/api/*` route requires `Authorization: Bearer <PANEL_TOKEN>`
  (constant-time compare; missing or wrong → 401; an unset `PANEL_TOKEN` → the panel refuses to start);
  `GET /api/simulations`, `GET /api/agents` (registry data for now); unknown ids → 404. No route mutates.
- The `panel` dependency group: `fastapi`, `uvicorn`, `httpx`, `docker` — kept out of the agent image.
- **Contract:** the TOML schema (`simulation`), the registry entry shape and the Bearer auth — ARCHITECTURE
  §Contracts / §The panel updated; pinned by tests.

**Dependencies:** None

**Expected result:**
`uv run uvicorn panel.app:app` serves the gated API; the agents load through the registry exactly as before.

**Acceptance criteria:**
- [ ] The registry has exactly one entry, `agora`; both TOMLs name it; the agents still start (HOMESERVER/ROOM_ID via the entry)
- [ ] Every `/api/*` route: 401 without / with a wrong token; unknown simulation / agent → 404
- [ ] **Tests:** registry load + validation (unknown kind, duplicate agent, missing fields), `load_config` through the registry (unknown simulation → error), the token gate on every route (TestClient), 404s, "no non-GET route exists"
- [ ] **Contract:** TOML `simulation` + the registry shape + Bearer auth — ARCHITECTURE updated, tests pin them
- [ ] **Gates:** lint, tests

### AGORA-034 — The read side: docker state, log tails, health probe, host metrics

**Description:**
Everything the cards need from docker, the homeserver and the host — read-only. Touches `panel/docker_read.py`,
`panel/health.py`, `panel/host.py`, `panel/app.py`, tests.

**What needs to be done:**
- A docker reader behind a small interface (fake in tests): container state (`running` / `exited` /
  `crashed` (non-zero exit) / `missing`), started-at → uptime, image short name; `logs(container, tail=200)`
  as parsed lines `{time, source, level, message}`; docker unreachable → `unknown` everywhere, never a 500.
  Container names come only from the registry (`server-<service>-1` per compose project).
- Health probe: `GET http://<service>:8008<path>` from the registry, every 30 s in the background, cached:
  `healthy` / `unreachable` / `unknown` + latency + checked-at.
- Host: uptime (`/proc/uptime`), memory (`/proc/meminfo`), load (`/proc/loadavg`), disk (`statvfs` of the
  mounted `state/`), OS line (`/host/os-release`, read-only mount), running containers count.
- Routes: `GET /api/health` (host + global status), `GET /api/simulations/{id}` (health + services),
  `GET /api/simulations/{id}/logs?service=…&tail=200`, `GET /api/agents/{name}` (container state, uptime),
  `GET /api/agents/{name}/logs?tail=200`. `tail` clamped to 1…500. Global status: all running / Matrix
  unreachable / Docker unreachable / Memory unavailable.

**Dependencies:** AGORA-033

**Expected result:**
The API reports live container state, uptimes, log tails, the health probe and host metrics, and degrades to
`unknown` when docker or the probe is down.

**Acceptance criteria:**
- [ ] States and uptimes from the docker reader; logs newest at the bottom, events only
- [ ] Docker unreachable → `unknown`, the probe still works; probe failure → `unreachable`
- [ ] **Tests:** the reader against a fake docker client (running / exited / crashed / missing / unreachable, log parsing), the probe with a fake transport (ok / timeout / refused), host parsing from canned `/proc` files, `tail` clamping, unknown service → 404 — no real docker, no network
- [ ] **Gates:** lint, tests

### AGORA-035 — Memory and usage views from state/

**Description:**
The agents' recorded life, read-only: the session summary, day memories, digests, plans (with the owner-only
deviation flag), the today block, and the token table. Touches `panel/memory.py`, `panel/app.py`, tests.

**What needs to be done:**
- `GET /api/agents/{name}/memory`: `summary` (text, written-at, words), `days` (date, weekday, words, text;
  newest first, the last `MEMORY_DAYS`… all present files), `digests` (year / month / week: period + text or
  missing), `plans` (year / month / week / day: period + items `{text, deviation}` — the hidden mutation tag
  becomes the boolean, never shown raw), `today` (text + the hour it was built for). Paths built only from the
  registry agent name + fixed patterns.
- `GET /api/usage?days=7&agent=…`: the v3.1 aggregation (`agents/usage.py`) by day × agent × kind, per-agent and
  overall totals, per-day totals for the chart, cost only when `PRICE_*_PER_1M` are set; `days` clamped 1…31;
  `agent` only from the registry.
- `state/` unreadable → `{"available": false}` for these views (the page greys them), never a 500; a missing
  file is "not written yet", not an error.

**Dependencies:** AGORA-033

**Expected result:**
The memory and usage endpoints return what the agents recorded; the numbers equal `usage_report.py`.

**Acceptance criteria:**
- [ ] Every memory kind returned with its metadata; mutation tags never appear in the output, only `deviation: true`
- [ ] `/api/usage?days=7` totals equal `usage_report.py --days 7` on the same files
- [ ] **Tests:** the views over a fixture `state/` (all kinds, missing files, an unreadable dir), plan parsing with and without tags, usage parity with `agents/usage.py`, `days` / `agent` validation
- [ ] **Gates:** lint, tests

## v3.3 scope notes

**Critical path:** AGORA-033 → AGORA-034 / AGORA-035 → AGORA-036 → AGORA-037 → AGORA-038.
**Phase DoD (ROADMAP.md §v3.3):** with the token the simulation and both agents show live state, without it
every API call is 401 and the page shows nothing; log tails, memory / plans / today, the token table (equal to
`usage_report.py --days 7`) and host metrics are visible; unknown names → 404 and no route mutates anything;
the panel is LAN-only and deployed by `server/deploy.sh`; the registry holds the single `agora` entry.
**Contracts touched:** the TOML `simulation` key and the registry shape, the Bearer auth (AGORA-033); the
compose service set and env names (AGORA-037).
**Owner steps:** the ufw rule for 8090 (sudo); the live checks; reading `PANEL_TOKEN` from `server/.env`.
**Not in this phase:** any action — start / stop / restart, forget, confirmations (v3.4); a settings view
(neither in the handoff nor in the DoD — dropped from the ROADMAP task); the fields nothing records (owner's
decision); detection of agents started outside the panel (owner's decision).
**Reconcile notes:** the host's docker group is gid 999 (`/var/run/docker.sock` root:docker 0660) → the panel
runs as `1000:1000` with `group_add: 999`; ufw is active but its rules need sudo → owner step; Ubuntu 22.04;
port 8090 is free. Host metrics need no broad host mount: `/proc` is the host's in a container, disk comes from
`statvfs` of the `state/` mount, the OS line from `/etc/os-release` mounted read-only. The registry lives at the
repo root (`simulations.toml`) because both images need it.
