### #1 — apply-path error masking
**Failure scenario:** the compose file is broken in a way the local preflight can't see (e.g. a host-only
env problem); `sudo -n docker compose up -d` fails with the real error silenced by `2>/dev/null`; the
fallback `docker compose up -d` fails too and its message blames the non-sudo path; the operator debugs the
wrong thing.
**Anchor:** `server/deploy.sh` apply step.
**Proposed fix:** plain `docker compose up -d` first (the docker group is the installed reality), `sudo -n`
only as the fallback, and no stderr suppression on the primary path.
