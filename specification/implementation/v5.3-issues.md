# v5.3 — Issues

Issues for phase **v5.3 — The agents answer in voice** (version **v5 — Voice: Hermes, the agents hear and speak**),
derived from the Tasks and DoD in [ROADMAP.md](../ROADMAP.md) §v5.3 and the contracts in
[ARCHITECTURE.md](../ARCHITECTURE.md). This file covers one phase; ids continue from the previous phase (AGORA-090 →
**AGORA-091…094**).

Every speaking agent gets its own voice. A line that goes out in voice is first checked as text (PASS, the
persona guard, the word cap, the duplicate), then spoken through the same pipeline as Hermes's digests, and sent as
an Element voice message — a reply to the owner's voice event when it answers one — followed by the same text, so
the room (and every other agent, who reads only text) sees the words. The cat may purr aloud.

**Owner decisions** (2026-10-18, at the phase start — the ROADMAP's proposals confirmed or changed):
- **Claude speaks too** (the ROADMAP had him in text; the owner made him a voice);
- **always:** an answer to the owner's voice is voiced, and every other line by a per-agent share
  `VOICE_REPLY_P` whose default is **1.0** (the ROADMAP proposed 0) — tunable per agent in the panel;
- **a monthly cap for all the speakers together: 50,000 characters** (`VOICE_MONTHLY_CHARS`; Hermes keeps his own
  150,000) — past it, text; **raised to 100,000** by the owner the same day, after the deploy;
- **the voices** (given 2026-10-18, gitignored `server/.env`): `ADA_VOICE_ID`, `BRUNO_VOICE_ID`, `KIT_VOICE_ID`,
  `CLAUDE_VOICE_ID` (Hermes's `HERMES_VOICE_ID` is v5.1's).

**Reconciled with the code (2026-10-18):**
- **Four send paths** in `agents/agent.py`, each a bare `room_send` of `m.text`: the reply (`reply`), the purr
  (`purr_later`), the cat's nudge (`nudge`), Claude's news (`news`). The text checks all run before them.
- **The voice pipeline** exists in `agents/herald.py` `send_voice`: synth → `encode_opus` → `client.upload` →
  `voice_content`. It reads Hermes's own cap and voice. It moves to a shared module both use.
- **The ElevenLabs key** lives in `server/hermes.env` and reaches only Hermes (a v5.1 contract, pinned by
  `tests/test_compose.py`). The speakers need it now, Claude included: Claude reads only `claude.env` plus names
  interpolated from the shared `.env`. A new `server/voice.env` holds the key alone, for exactly the members who
  speak in voice.
- **The settings schema** has agent-scoped settings (`service` None) whose env base is one shared name. A
  per-agent voice id needs a per-agent base: `<LOCALPART>_VOICE_ID`, aliased to `VOICE_ID` at an agent's start,
  so the panel's per-agent override works as for every agent setting.
- **The owner's voice** is known to a speaker as a transcript it accepted (`_heard`, v5.2). The voice event it
  replies to is in the transcript's `m.in_reply_to`.
- **Audio from members.** Every agent logs every audio event. With voiced replies, each member's voice message
  would add a line to every other agent's log and to Hermes's.

## v5.3 — The agents answer in voice

### AGORA-091 — The `voice` capability, the voice settings, and the pure decisions

**Description:**
Who may speak, with which voice, how often, and within what budget. The files are `agents/roster.py`,
`agents/settings.py`, a new `agents/speech.py` (its pure part) and `agents/usage.py`.

**What needs to be done:**
- **`agents/roster.py`:** a `voice` capability, on by default for `persona`, `creature` and `assistant`, and never
  for a `herald` (his voice is his digest's).
- **`agents/settings.py`:**
  - `VOICE_ID`: kind `id`, agent scope, `cap:voice`, group «Голос», default `""`.
  - `VOICE_REPLY_P`: float 0..1, agent scope, `cap:voice`, default **1.0** (the owner).
  - `VOICE_MONTHLY_CHARS`: int 0..1,000,000, service `matrix-chat`, `cap:voice`, default **50000** (the owner);
    0 means text only.
  - `start()` aliases the agent's own `<LOCALPART>_VOICE_ID` to `VOICE_ID` when `VOICE_ID` is not set, so each
    agent's base is its own and the panel's override is per agent.
  - The groups: «Голос» in the agents' groups and in the service groups.
- **`agents/speech.py` (pure):**
  - `voice_due(answers_owner_voice, event_key, localpart, p)`: always True when answering the owner's voice;
    otherwise the deterministic `uniform(event_key, "voice:" + localpart) < p`;
  - `voiceable(text)`: False for an action purr (`*потягується*`) — a voice would read the stars' word aloud;
  - `speakers_month_chars(records, month, heralds)`: the month's ok `tts` characters of every member but the
    heralds.
- **`.env.example` / `server/.env.example`:**
  - `VOICE_REPLY_P` and `VOICE_MONTHLY_CHARS` with the code defaults;
  - `ADA_VOICE_ID=`, `BRUNO_VOICE_ID=`, `KIT_VOICE_ID=` and `CLAUDE_VOICE_ID=` as names, empty.
- **ARCHITECTURE:**
  - §Contracts: the capability, the settings and the env names;
  - §Configuration: the three settings and the per-agent voice id.

**Dependencies:** None

**Expected result:**
Each speaker knows its voice, how often it speaks and how much is left this month, all as pure functions and
settings.

**Acceptance criteria:**
- [ ] **Tests:**
  - `tests/test_roster.py`: `voice` on persona, creature and assistant, never on a herald;
  - `tests/test_settings.py`:
    - the three settings, their scope and service, and their defaults read by the code;
    - the alias gives Ada `ADA_VOICE_ID`;
    - a panel override for one agent changes only that agent;
  - a new `tests/test_speech.py`:
    - `voice_due` — owner voice always; p=0 never; p=1 always; deterministic per event and agent;
    - `voiceable`;
    - `speakers_month_chars` — month bounds, failed lines out, heralds out;
  - `tests/test_compose.py`: the env examples equal the schema defaults.
- [ ] **Contract:** capability, settings and env names in ARCHITECTURE, pinned by the tests above.
- [ ] **Gates:** lint, tests.

### AGORA-092 — The voiced line: one shared voice pipeline, every speaker's send path

**Description:**
Move the synth → encode → upload → `m.audio` pipeline into `agents/speech.py`, used by Hermes and by every speaker,
and send every speaker's line through one `send_line`. The files are `agents/speech.py`, `agents/agent.py` and
`agents/herald.py`.

**What needs to be done:**
- **`agents/speech.py` `voice_message(client, tts, text, room_id, filename, reply_to=None)`:**
  - synth → `encode_opus` → `upload` → `voice_content`, with `m.relates_to.m.in_reply_to` when replying;
  - returns why it could not be voiced (None when sent), and whether the synth was attempted and ok, for the usage
    line.
- **Hermes** uses it (his behaviour unchanged).
- **`Agent`:**
  - pops `ELEVENLABS_API_KEY` at start: Claude's CLI never inherits it;
  - builds its `ElevenLabsTTS` from `VOICE_ID` when the key and a valid id exist; otherwise logs `voice off: …`
    once.
- **`Agent.send_line(room_id, text, event_key, answering)`** replaces the four bare `room_send`s:
  - the reply: `answering` is the message it answers;
  - the purr: the event;
  - the nudge and the news: their marker.
  - **Voiced** when the agent has `voice`, a voice, `voiceable(text)`, `voice_due(…)`, and
    `speakers_month_chars + len(text) ≤ VOICE_MONTHLY_CHARS`.
  - Answering the owner's voice means the answered message is a transcript the agent accepted. Its voice event id
    is kept with it (`_heard`), so the voice message replies to it.
  - The order: the `m.audio`, then the same text as `m.text`. The other agents read only text, so the turn-taking,
    the history and Hermes's digests are unchanged.
  - A failed step sends the text alone, logged by reason.
  - A `tts` usage line per synth.
  - Never a word in a log.
- **Members' audio** (another agent's voice) is not logged by the speakers or by Hermes. Only the owner's and a
  stranger's are.
- **ARCHITECTURE:**
  - §Voice messages: the shared pipeline and the voiced line;
  - §Message flow: the voice-then-text order, and members' audio never handled;
  - §The herald: on the shared module.

**Dependencies:** AGORA-091

**Expected result:**
Spoken to in voice, Ada, Bruno, the cat and Claude answer in their own voices, and the text reads the same in the
room. Within the share and the cap, every other line is voiced too.

**Acceptance criteria:**
- [ ] **Tests** (nio, Gemini, the SDK, TTS, ffmpeg and the upload mocked):
  - a reply to an owner's voice transcript → `m.audio` replying to the voice event, then the same `m.text`;
  - `VOICE_REPLY_P` 0 → a typed answer stays text; 1 → voiced;
  - the cap reached, no voice id, no key, or a TTS failure → text only;
  - PASS, the guard and a duplicate → nothing at all;
  - an action purr → text, a «Мрррр.» → voice;
  - the nudge and the news voiced by the share;
  - Claude pops the key before his CLI;
  - members' audio not logged;
  - Hermes's digest tests unchanged on the shared module;
  - no text in logs.
- [ ] **Contract:** §Voice messages and §Message flow in ARCHITECTURE, pinned by the tests above.
- [ ] **Gates:** lint, tests.
