## Findings

### 1. 🟡 One offer, handled again on every poll — `agents/bridge.py` `_initiative`
**Scenario:**
- Lumi keeps one offer at a time, fresh for 30 minutes unless a new room line arrives (Q16). The bridge never tells
  Lumi it dropped an offer. A drop is never acked, by design.
- So an offer dropped by the persona rule while the room stays quiet comes back on the next poll, a minute later, with
  the same `initiative_id`. Each time:
  - it is dropped again;
  - a new `initiative` usage line counts the same compose again;
  - `dropped` grows by one.

  That can happen up to 30 times, until Lumi's offer goes stale.
- After a send that raised, for example a timeout on a send the homeserver did accept, the same offer comes back and is
  posted again. The room would see her line twice.

**Fix:** handle an offer once by its id. The bridge keeps the ids it has handled, posted or dropped, bounded to the
last few. An offer seen again is passed over: no usage line, no count, no post. `last_poll` reads `repeat`.

### 2. 🟡 His privacy rests on Lumi's guard alone — `agents/bridge.py` `_offer_dropped`
**Scenario:**
- The contract's `never` reads «an initiative about the owner or their talks alone, or one carrying «Ich»». Lumi's
  name guard enforces it.
- The bridge posts any offer exactly as written; its only check is the persona rule. If Lumi's guard regresses, an
  offer naming «Ich» reaches the room. The phase's DoD is «never about him; nothing of his private talk reaches the
  room», and the owner set that rule himself («в Агорі вона нічого не каже про мене»).
- A turn may name him: she answers in the room. An initiative may not, by the contract.

**Fix:** a second fence before posting. `names_owner(text)` (the room's forms of him, «Ich») drops the offer as
`names him`, never posted and never acked, like the persona rule.

### 3. 🟡 An offer id of dots — `agents/lumi_api.py` `INITIATIVE_ID_RE`
**Scenario:**
- `^[A-Za-z0-9._~-]{1,128}$` accepts `.` and `..`.
- `urllib.parse.quote("..", safe="")` returns `..`, so the ack's path becomes `/v1/initiative/../posted`. An HTTP
  client or server normalizes that to a different route.
- The id comes from Lumi, so this needs Lumi off its contract. Still, the client is meant to post only URL-safe ids.

**Fix:** an id starts with a letter or a digit (`^[A-Za-z0-9][A-Za-z0-9._~-]{0,127}$`), so no id is only dots.

### 4. 🟡 The card's «no initiative» for a bridge without it — `panel/static/app.js` `bridgeLines`
**Scenario:** a bridge whose TOML sets `initiative = false`, against a Lumi on `agora` 1. The card says «no initiative:
agora 1», but she would offer nothing on any version.
**Home:** backlog. No such bridge exists, and the card would need the agent's capabilities passed in.

## What's solid

- **The pace lives in one place.**
  - `initiative_due` is pure, with the clock injected. The bridge polls only when every rule holds, so Lumi's
    background compose follows the room's pace (Q14).
  - A simulated day over 25 seeds never exceeds the cap, never opens a line inside a running wave, never comes twice
    in a row, and never comes outside her hours.
- **Remembered only when seen.**
  - Only a posted line is acked, with its own event id.
  - A drop is never acked, so Lumi never remembers it.
  - An ack Lumi never got is kept as ids only, retried across a restart, and given up after a day, as the contract
    keeps offers.
- **No collisions with her turns.**
  - Agent's `_reply_pending` stays true for the whole reply, so a poll never runs beside her turn.
  - The pre-post check, that the room's last line is unchanged, drops an offer the moment anyone speaks.
- **Her line is an ordinary agent line.** Her own line enters the shared timeline from the sync, so the next poll sees
  it is hers (never twice in a row). The others answer her by R2.
- **Nothing of hers is kept.**
  - `InitiativeResult` keeps `outcome`, `initiative_id`, `text` and `stats` alone, and shows no text in its `repr`.
  - The state, the usage lines and the log hold counts, times, ids and reasons only (tested by `caplog` and the
    state file).
- **`"agora": 1` keeps v8.2.** The bridge offers nothing and keeps answering. This is the state on prod until Lumi
  v3.4 is deployed at G8.
- **Settings that cannot take the room down.** They are read only by the member holding `initiative`, and the idle is
  never under `BOT_WINDOW_S`.
