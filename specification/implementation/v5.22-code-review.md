## Findings

### 1. 🟠 An answers line without `door` takes Analytics down — `agents/usage.py:974`, `:1081`

**Failure scenario:**
- `_answer_ok` checks `ts`, `agent`, `place`, `answered`, `by`, `parts` and the two times, but never `door`.
- `analyze_detail` groups the answers by `(agent, place, door, by, answered)`, with `a["door"]`.
- A line without `door` raises `KeyError`. A `door: null` beside `"telegram"` in one group raises `TypeError` in
  `sorted()`.
- `analytics_view` runs `analyze_detail` before it answers, so the route is a 500 and every view breaks, Cost
  included.
- The contract says a corrupt line is skipped and counted.

**Fix:** `door` must be one of `ANSWER_DOORS` (`matrix`, `telegram`), as the writer's docstring names them. A test
with a line missing `door` and one with `door: null`: both counted as corrupt, and the analysis answers.

### 2. 🟠 A summary both models block is retried on both, every 15 minutes — `agents/agent.py:3793`

**Failure scenario:**
- Her session holds lines Flash blocks at the prompt stage (six times on 2026-11-02). Since 7a409f3 3.1 Pro writes
  it once more, and Pro may block it too.
- `summarize()` returns False and keeps the session. `idle_watcher` tries again every `SESSION_IDLE_S` (900 s) while
  she is idle.
- Before v5.22 that was one Flash call. Now each retry is Flash plus a 3.1 Pro call over the same blocked prompt.
  That is up to ~96 Pro calls a day, about $2 a day, and it keeps growing with the session.

**Fix:** remember the length of the session Pro blocked (`_summary_pro_blocked`). While the session has no new line,
a Flash block is not sent to Pro again; a new line clears it. A test drives the same session twice (one Pro call),
then a longer one (Pro again).

### 3. 🟠 `wait_ms` counts from her own last line — `agents/agent.py:1059`, `:1152`, `:2110`

**Failure scenario:**
- `asked_ms = self.last_private_ms`, and both her answer (`:1152`) and her line after a кружечок (`:2110`) set
  `last_private_ms`.
- He sends A. She answers it in 10–40 s on 3.1 Pro, and meanwhile he sends B. The first pass answers A and sets
  `last_private_ms` to her answer's time.
- The second pass answers B with `asked_ms` = her previous answer's time, so B's wait is under-reported.
- ARCHITECTURE pins `wait_ms` «from that message's own time», and it is the phase's main number.

**Fix:** `_his_last_ms`, set only in `private_line` (his line's own time), is the answer's `asked_ms`. A test: A,
then B while she answers A, then B's `wait_ms` counted from B.

### 4. 🟠 The facts seed's usage lines are lost — `agents/facts.py:408`, `agents/llm.py:92`

**Failure scenario:**
- Since AGORA-183 `GeminiClient._report` passes `latency_ms=` to its sink.
- The seed CLI's sink is `sink(kind, model, meta, ok, blocked=None)`, so every call raises `TypeError`.
- `_report` catches it and logs «usage accounting failed», so the seed's calls never reach `kira.usage.jsonl`, the
  cost or Analytics.

**Fix:** the seed's sink takes `latency_ms` and writes it. It becomes `seed_sink(...)` at module level, so a test can
call it through `GeminiClient._report`.

### 5. 🟡 The silence line can name the wrong cause — `agents/agent.py:1065`, `agents/private.py:72`

**Failure scenario:**
- `LAST_BLOCK` and `LAST_SILENCE` are reset at the answer's start, before `ensure_today` and `ensure_mood`, which call
  Gemini in the same task.
- In the backup's mode Gemini is never asked for the answer, so a blocked today or mood call reads «блок gemini (…),
  backup не відповів».
- A backup reply that `_compose` dropped (e.g. only voice tags) also reads «backup не відповів».

**Fix:** reset both right before `_private_text`. When the backup wrote and a silent reason is set, the line names
the reason. Tests for both.

### 6. 🟡 A non-UTF-8 byte is a 500 — `panel/memory.py:437`, `:448`

**Failure scenario:** `_all_usage_records` and `_all_answer_records` catch only `OSError`. A torn write or one bad
byte raises `UnicodeDecodeError`, a `ValueError`, out of the route.

**Fix:** read with `errors="replace"`, so the line is corrupt (skipped and counted). A test for both files.

### 7. 🟡 Media's cost is not Cost's — `agents/usage.py:1159`

**Failure scenario:** `media_cost` calls `cost()` directly. A period whose only photo calls failed with no counts,
with the image model priced in `PRICE_MODELS` and the default pair unset, shows Media's photo cost «—», while Cost
shows $0.

**Fix:** `_atom_cost(acc, prices)`, Cost's own rule. A test.

### 8. 🟡 The persona scan misses the private canon and story — `tests/test_logic.py:94`

**Failure scenario:** `persona_files` reads only `canon` and `life`. ARCHITECTURE says every persona's canon and life
story is scanned for a word that calls her a model or a bot. `kira.life.private.md` is not scanned at all, and
`kira.private.md` is scanned only by its own test.

**Fix:** `canon_private` and `life_private` join `persona_files`.

### 9–16. Deferred

- **#9, the trace burst.** It depends on Telegram throttling a 3–5 message burst to the owner. `TRACE_CALLS` is a
  diagnostic he turns off.
- **#10, `voice_sent`.** It needs an Agora send and a Telegram send in the same instant, and only skews a count.
- **#11 and #12, malformed lines.** No writer of ours makes them.
- **#13, the browser's hour.** It matters only from another timezone.
- **#14, the sparklines.** Cosmetic.
- **#15, Reset for an On \| Off switch.** A UI addition. The overrides file can still be cleared in the panel's
  Settings JSON.
- **#16, DST.** Two days a year.

## Architecture impact

- **#2:** ARCHITECTURE §Memory (session summary) now says that once the reply model blocks a summary too, no retry
  sends it there again until the session has a new line.
- **#5:** ARCHITECTURE §the owner's commands («Never a bare silence») now names the backup's own reason, and says the
  block and the reason are reset right before her answer.
- **#1, #3, #6:** the code now does what the contracts already said: an answers line's `door` is `matrix` or
  `telegram`, `wait_ms` counts from the answered message's own time, and a corrupt line is skipped and counted.

## What's solid

- **The context variables are per task and set at each call:**
  - `LAST_BLOCK`, `_CALL_T0`, `PROMPT_PARTS`, `_LAST_PARTS`, and the photo and video timers;
  - every `GeminiClient` method starts its clock before it reports;
  - the prompt's parts attach only to the prompt this task built last.
- **The live switches:**
  - `live_value` falls back to the env and the default on a missing, corrupt or invalid override;
  - a live name is never applied at start, and its save restarts nobody, while a mixed save still restarts for the
    rest;
  - On \| Off renders only for choices exactly {on, off}.
- **The private canon and story are chosen in one place** (`prompt_layers`, a private prompt). Every other builder
  (summaries, talk, thoughts, events, plans, digests) keeps the whole canon and story, and a missing or empty file
  refuses to start.
- **`/unblock`:**
  - it reads only lines open to Gemini and leaves his waiting lines alone;
  - it marks through the archive's guards;
  - it logs and answers with counts, speakers and times only.
- **The analysis:**
  - the nearest-rank percentile is right on 1, 2 and n values, and None on none;
  - the previous period has the same length;
  - the media hours count today only up to now;
  - the structure's shares sum to 1;
  - v1–v6 lines read the new fields as null;
  - every server value in `app.js` goes through `esc()`.
