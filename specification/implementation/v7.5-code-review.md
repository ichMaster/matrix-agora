## Findings

### 1. 🟠 A failure on the cache never backs off — `agents/llm.py:244`
**Scenario:** the call that uses the cache keeps failing — the model rejects `cached_content` with this config, or the
cache is gone on Google's side. The `except` runs `forget()` and deletes the cache, but never starts the backoff. On the
next answer the start was seen moments ago and nothing is held, so the planner makes a new cache (`first`) again. In the
mocked run, 6 answers made 5 caches, deleted 5 and made 11 model calls. Each answer pays to create ≈ 44k tokens, a
failed call and a plain call, for as long as the failure lasts.
**Fix:** `self.cache.failed(channel, now)` beside `forget()`, as a failed `create` already does.

### 2. 🟠 A timeout on the cache retries twice more and drops the cache — `agents/llm.py:233-252`
**Scenario:** `_within` already tries twice (`REPLY_TRIES` 2 × 90 s). When both tries on the cache hang, the `except`
deletes the cache and calls `_within` again without it, for two more tries. On a bad network (2026-11-04) her answer can
wait up to 6 minutes instead of 3, over 4 calls that may each be billed. A timeout says nothing about the cache, yet the
cache is deleted, and the next answer makes it again.
**Fix:** on `TimeoutError`, keep the cache and return `None` as a plain call does. Forget the cache and retry plain only
on other exceptions.

### 3. 🟡 Codex at its limit sends Gemini a prompt it already split — `agents/codex_cli.py:215, 248`
**Scenario:** `CodexAnswers.reply` splits first and then hands `_on_gemini` `system=start` and
`history + SEPARATOR + tail`. Gemini splits again: `split_prompt(start, start)` gives an empty tail. The separator and the
whole tail become "history lines": they go into the cache, including «Зараз HH:MM», and the message ends with a bare
separator. The next answer sees a changed history, which puts her private channel into start-only mode for 2 hours.
**Fix:** hand `_on_gemini` the transcript and the instruction as they came, as `ClaudeClient._instead` does.

### 4. 🟡 The `cache` lines are counted as calls in Analytics · Prompts — `agents/usage.py:1234`
**Scenario:** `prompted` takes every line with a `prompt_tokens` value. A renewal line has 0 tokens and a make line has
the cache's size, and both count as calls in the services, models, kinds and agents tables. With 4 answers of 20k
tokens, one make and 3 renewals, Gemini shows 8 calls with a mean of 11,875 instead of 4 calls with a mean of 20,000.
**Fix:** leave out `kind == "cache"` when building `prompted` and `p_prompted`.

### 5. 🟡 A renewal records a whole TTL of storage — `agents/llm.py:291`
**Scenario:** a cache in use is renewed when less than half its life is left, which adds `ttl − remaining` seconds.
The renewal line still records `ttl` seconds of storage. Over a long talk, storage is overstated by up to about 2×.
Storage is $4.50 per 1M tokens an hour, so the error is in the money the owner reads to judge the 1-hour cache.
**Fix:** record the seconds the renewal added: the new expiry minus the old.

### 6. 🟡 Storage on a renewal-only day costs $0 — `agents/usage.py:838`
**Scenario:** a cache made before midnight and renewed after it. That day's only `cache` lines for that agent and model
are renewals. They have no priced prompt or output, so `_atom_cost` returns $0.0 before it reaches `cost()`. `cost()`
alone gives $0.01125 for the same row.
**Fix:** count stored token-seconds as billable in `_atom_cost`.

### 7. 🟡 The old cache stays stored after the start changes — `agents/gemini_cache.py:105`
**Scenario:** her start changes, for example when a new hourly talk summary is written. The next answer is `quiet`
(plain), and the held cache, now of no use, stays stored until a second answer with the new start replaces it. At the
end of a talk that second answer never comes, so the old cache lives out its TTL, now an hour: $0.045 for each 10k
tokens it holds.
**Fix:** when the held cache's start or model differs and it is still alive, the `quiet` plan names it as `old`.
`_cache_for` deletes it, and the planner stops holding it.

### 8. 🟡 `CLAUDE_WARM=off` documented as it was in 7.3.1 — `specification/ARCHITECTURE.md:764`, `agents/settings.py:323`
**Scenario:** since AGORA-257 every voice answer on Claude is split, on the cold path too (ARCHITECTURE line 613). The
settings table and the setting's description in the panel still say `off` means "no split, the whole instruction as
the system prompt".
**Fix:** the table row and the setting's text say `off` means no CLI started ahead: the start as the system file, the
history and the tail as the message.

### 9. 🟡 A start-only cache keeps the history out while it is used — `agents/gemini_cache.py:95`
**Scenario:** a cache with `lines == 0` matches any history. The use branch never checks `start_only_until` or the
growth, so after the 2 hours it holds history again only when the start changes. In practice her start changes with
each hourly talk summary, and Устина's 6-hour window no longer slides.
**Home:** v7.6, which replaces her window and summaries (a short live window, day and week gists).

### 10. 🟡 Storage that outlives its use — `agents/llm.py`
**What remains after #5 and #7:**
- A cache deleted early is still recorded for its whole TTL.
- Nothing deletes the held caches when the agent stops; restarts are rare.
- A `create` that timed out after 60 s or was cancelled may still succeed on Google's side and live out its TTL.

**Home:** backlog. The storage at stake is bounded by `GEMINI_CACHE_TTL_S`.

### 11. 🟡 Small accounting gaps — `agents/llm.py:234`
`self._start()` runs after `_cache_for`, so `latency_ms` leaves out a cache's creation, which happens rarely. A failed
call on the cache writes no usage line.
**Home:** backlog.

### 12. 🟡 Anthropic's cache writes at 1.0× — `agents/usage.py:253`
`input_tokens` includes the cache writes, which are priced at the input price instead of 1.25×. Only Sonnet on the API
is affected, and the companions are not on it.
**Home:** backlog.

### 13. 🟡 The scan's layout (unconfirmed) — `agents/agent.py:2165`
The scan still sends her whole private prompt as the system instruction, with the history as the content. Answers now
send the start as the system and the history and the tail as the message. A prompt-stage block could judge the two
layouts differently. This has not been seen.
**Home:** backlog, to be checked on the next block.

## What's solid

- **What goes with the cache:** with `cached_content` set, the call sends no `system_instruction` and no tools. The
  model, the start and the fingerprint are all checked before a cache is used.
- **The plain retry:** it sends the start as the system and the whole history and the tail, with nothing duplicated.
- **The prefix check:** an exact line count and a hash of the lines, so different content cannot pass.
- **Concurrent calls:** her private channel is serialised by `_private_pending` and Agora by `_reply_pending`, so
  `plan()` and `made()` cannot interleave in normal flow.
- **The split:** the tail reaches the model on every answer path (Gemini plain and cached, the Claude CLI started ahead
  and cold, OpenAI, Anthropic, Codex, the Claude fallback to Gemini). Summaries and background calls keep their whole
  prompt. The start is an exact prefix of the prompt.
- **The room's window:** only `_add_context` writes the room's history. `history_ts` and `wide_ts` stay in step through
  the purr collapse and the caps, and the restart's backfill passes the server's timestamps. A length mismatch falls
  back to the whole window.
- **Prices:** a cached part is priced once, at `min(prompt, cached)`. The storage units are right (token-seconds / 3600 /
  1e6 × $ per 1M an hour). Two to four numbers parse, and old lines without the new fields still read.
- **Invariants:** no text in the new log or usage lines. Nothing new calls a persona a model or a bot.
- **The `speaker` scope, the Dockerfile's stages and compose** are fine.

## Architecture impact

- **The usage line (`state/<name>.usage.jsonl`):** a `cache` renewal line's `cache_ttl_s` is the seconds the renewal
  added, no longer the TTL. A made line still carries the TTL (ARCHITECTURE §State files, #5).
- **The cache's life (ARCHITECTURE §Prompt assembly, v7.5):**
  - a failed call on it backs off 5 minutes (#1);
  - a hang keeps it, with no plain retry (#2);
  - a new start deletes it at the first answer with that start (#7).
- **`CLAUDE_WARM`:** the settings table records that `off` is no CLI started ahead alone (#8).
- **ROADMAP v7.6** carries #9 under "The cache over the new window".
