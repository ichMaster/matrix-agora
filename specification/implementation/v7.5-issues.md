# v7.5 — Issues

Issues for phase **v7.5 — The prompt for the cache: what changes slowly first, read from the cache** (version **v7 —
Claude for everyone: every agent on the owner's subscription**), derived from the Tasks and DoD in
[ROADMAP.md](../ROADMAP.md) §v7.5 and the contracts in [ARCHITECTURE.md](../ARCHITECTURE.md). This file covers one
phase; ids continue from the previous phase (AGORA-254 → **AGORA-255…259**).

Every agent's prompt is laid out as a slow start (the same from call to call) and a per-call tail. On Gemini — Кіра's
and Устина's answers on 3.1 Pro — the start goes into an explicit context cache, as Lumi does. Their history window
moves in steps so its start repeats, and the tail goes after the history, next to his line. On Claude and the other
answer models the same split reaches their own caches. The memory itself (a shorter live window, gists, recall by a
tool) is v7.6's, and the panel for Claude is v7.7's.

**Reconciled with the code (2026-11-12):**
- **Today's order breaks every cache.** `build_instruction` (`agents/logic.py`) assembles canon → life → **world** (the
  place and the time to the minute) → memories → plans → today → mood → thoughts → pastlife → nudge → facts →
  agora_now → recalled → talk → summary → private → move → asked → voice → rules. Only the canon and the life repeat
  from one call to the next: the third part changes every minute. That is why 3.1 Pro read 0.1% of 52M prompt tokens
  from its cache in the week of 2026-11-04 … 10 (docs/companions-gemini-cost.md).
- **The implicit cache is not enough.** A test of 2026-11-12 sent 23 calls of 3.1 Pro preview with an identical
  43,800-token start and got 0 cached tokens. On Gemini the cache must be made explicitly. google-genai 2.28 has
  `client.aio.caches.create(model, config=CreateCachedContentConfig(system_instruction, contents, ttl))`, `update`
  (TTL), `delete`, and `GenerateContentConfig(cached_content=…)`.
- **One prompt string, split later.** `build_prompt` returns one string, and `_LAST_PARTS` / `PROMPT_SLOW` carry its
  slow prefix (v7.2: canon + life, `slow_part`). Many callers keep the string whole: `keep_prompt`, the scan, the
  backup and the tests. So the order changes inside it, the slow prefix grows to the whole start, and the split
  (system = start, message = history + tail) happens where each client sends it — as the Claude client's warm path
  already does (`split_prompt`).
- **How often each layer changes:**
  - memories, plans, mood, life — by the day;
  - facts (`prompt_facts` is deterministic) — when she keeps one;
  - summary — at a session's end;
  - talk — by the hour, its labels relative by the day (`ago`);
  - world, today, thoughts, agora_now, recalled, private (her brief with the style line, topics and skills), move,
    asked — by the call;
  - voice and rules — never, but they stay last, as the freshest instructions (ROADMAP).
- **The history window is by the hour.** `window_start` (`agents/private.py`) takes every line from `now − hours`
  (Кіра's `PRIVATE_HISTORY_HOURS` 6), at least `PRIVATE_HISTORY_MIN` lines, and his lines since her last one. Its
  start moves with the clock. Its time lines (`history_times` → `ago`) change only by the day, so they keep a
  repeating start within a day.
- **Gemini's usage lines already carry the cached count** (`cache_read_tokens` from `cached_content_token_count`).
  `PRICE_MODELS` is `model=in/out` and prices every input token at full price.

## v7.5 — The prompt for the cache

### AGORA-255 — The prompt by how often it changes: the slow start first, the per-call tail after it

**Description:**
`build_instruction` assembles the same layers in a new order — what changes slowly first, then what changes every call
— and `build_prompt` hands the whole start on as the prompt's slow part. Touches `agents/logic.py`
(`build_instruction`, `slow_part`), `agents/agent.py` (`build_prompt`, `_LAST_PARTS`), the prompt-order tests,
`specification/ARCHITECTURE.md` §Prompt assembly.

**What needs to be done:**
- **The new contract order.**
  - **The start**, slow, first: canon → life → memories → plans → mood → last-session memory (`summary`) → facts
    (private) → talk (private).
  - **The tail**, per call, after it: world (place and time) → today → thoughts → pastlife → nudge → agora_now →
    recalled → private (her brief, its style line, topics, skills) → move → asked → voice → rules.
  - Empty sections are skipped as now, and every invariant holds (nothing of her future, no word that she is a model,
    PASS as now).
- **The start as one exact prefix.** `build_prompt` sets `_LAST_PARTS` to (prompt, parts, start), where the start is
  exactly the prompt's prefix up to the tail. `slow_part` returns it (v7.2's canon + life grows to the whole start),
  so `PROMPT_SLOW` carries it to every client.
- **The same layers, nothing lost.** A test builds a prompt in the old order and in the new one and compares the
  multiset of sections.
- **The backup's prompt** (NovelAI) is the same string in the new order. Its budget cuts (`fit_budget`) are unchanged.
- **The scan and `keep_prompt`** keep the whole string as now (pinned by their tests).

**Dependencies:** None

**Expected result:**
Every agent's instruction starts with the same text from call to call within the hour, and the code knows exactly
where that start ends.

**Acceptance criteria:**
- [ ] The layers in the new order; `slow_part` / `PROMPT_SLOW` is the whole start; the same sections as before.
- [ ] **Tests:**
  - the order;
  - the start as an exact prefix, unchanged by the time, the recall, the move or the style line;
  - the multiset of sections unchanged;
  - the backup's prompt and the scan still work on the whole string.
- [ ] **Contract:** ARCHITECTURE §Prompt assembly rewritten (the start and the tail), pinned by the prompt-order tests.
- [ ] **Gates:** lint, tests.

### AGORA-256 — Gemini: the tail after the history, the explicit context cache, the history window in steps

**Description:**
On Gemini her start goes as the system instruction in an explicit context cache, as Lumi does, and the history and the
tail go as the message. Her history window moves in steps, so its start repeats too. Touches `agents/llm.py`
(`GeminiClient.reply`, a new cache manager), `agents/responder.py` (`LlmResponder`: the split), `agents/private.py`
(`window_start`), `agents/agent.py`, `agents/settings.py`.

**What needs to be done:**
- **The split.** An answer kind with a known start (`PROMPT_SLOW`) is sent as `system_instruction` = the start and
  `contents` = the history transcript, then the tail after a neutral separator — next to his last line. Without a
  known start, as now.
- **The history window in steps.** `window_start` keeps the hour-based rule, but its start snaps down to a step
  (`PRIVATE_HISTORY_STEP_H`, default 2 h). So the window is `PRIVATE_HISTORY_HOURS` to `+step` long, and between two
  steps a new line only adds to its end. The floor and his unanswered lines rule as now.
- **The explicit cache** (`agents/gemini_cache.py`, a pure plan over plain data plus a thin SDK layer):
  - **What it holds:** the start, plus the history from the window's start up to the lines already there when it is
    made (all but the last few), as `CreateCachedContentConfig(system_instruction, contents, ttl)`. The call then sends
    `cached_content` and only the rest of the history and the tail.
  - **Its key:** a fingerprint (sha256 of the model, the start and the cached history's text).
  - **Its life:** `GEMINI_CACHE_TTL_S` (default 600), renewed by `update` when a call uses it in its last half.
  - **When it is made:** only on the **second** answer with the same start within its life, so a quiet hour stores
    nothing.
  - **When it is made again:** when the start changes, when the window steps, or when the uncached history grows past
    `GEMINI_CACHE_REBUILD_LINES` (default 40).
  - **Cleanup:** the old one is deleted at once, so its storage stops.
  - **On failure:** a cache that cannot be made, has expired or is refused means a call without it, never silence; a
    failure to make one is not tried again for a few minutes.
- **Which calls.** Her answer kinds (`private`, `private_nudge`, `reply`) on her Gemini reply model, Кіра's and
  Устина's alike. The background is unchanged.
- **The settings** (`cap:private`, in the panel): `GEMINI_CACHE` on|off (default on), `GEMINI_CACHE_TTL_S`,
  `PRIVATE_HISTORY_STEP_H`. Off is today's plain call.
- **One live check, with made-up lines, its cost said first (about $0.05):** a cached start plus a request whose
  contents follow the cached contents (two user turns in a row) answers, and its usage line shows the cached tokens.

**Dependencies:** AGORA-255

**Expected result:**
Her second answer within the cache's life reads the start and most of the history from Gemini's cache, at a tenth of
the price.

**Acceptance criteria:**
- [ ] The split on Gemini; the window's steps; the cache made, reused, renewed, made again and deleted as above; a call
  without it on any failure.
- [ ] **Tests**, with the SDK faked:
  - the cache's plan (pure): first call none, second makes, reuse, step, start change, rebuild past N lines, expiry,
    failure backoff;
  - the request (`cached_content`, no system, only the rest of the history and the tail);
  - the window's steps (pure);
  - nothing reaches the network.
- [ ] **Contract:** the message's shape on Gemini (history then tail) and the settings' names, in ARCHITECTURE, pinned
  by the tests.
- [ ] **Gates:** lint, tests.

### AGORA-257 — Claude and the other answer models on the same split

**Description:**
The Claude CLI, the OpenAI and Anthropic APIs and Codex get the same split: the start as their system prompt, the
history and the tail as the message. Each provider's own cache then reads the start. Touches `agents/claude_sdk.py`
(`ClaudeClient._query`, `split_prompt`), `agents/openai_api.py`, `agents/anthropic_api.py`, `agents/codex_cli.py`.

**What needs to be done:**
- **Claude (the room on Haiku, Hermes on Sonnet, a companion's Opus):**
  - The system prompt's file is the start, and the message is the transcript then the tail. This holds on both the
    warm path and the cold one.
  - The warm key is the start, so one CLI started ahead serves a whole hour.
  - `CLAUDE_WARM=off` keeps only "no CLI started ahead".
  - The CLI's own cache (an hour) then reads the start from the second call on.
- **The Anthropic API (Sonnet):** the system as a block with one `cache_control` breakpoint — Lumi's single
  breakpoint, its read at $0.20 per 1M.
- **The OpenAI API (GPT-6.1 Sol):** the start as `instructions`, the history and the tail as the input, and a
  `prompt_cache_key` per companion, so OpenAI's automatic prefix cache finds it.
- **Codex:** the start as `model_instructions_file`, the history and the tail by stdin.
- Before coding the Anthropic and OpenAI fields, check them against the installed SDKs (anthropic 2.8, openai 3.49);
  never guess.

**Dependencies:** AGORA-255

**Expected result:**
On every answer model the start is the system prompt, read from that provider's cache from the second call on.

**Acceptance criteria:**
- [ ] Each client's request has the start as its system prompt and the history then the tail as its message.
- [ ] **Tests:**
  - the Claude client's system file and message on the warm and the cold path, and its warm key;
  - the Anthropic `cache_control` block;
  - OpenAI's `prompt_cache_key`;

### AGORA-258 — The cache in the numbers: its lines, its prices, Analytics' share, why a call missed

**Description:**
The cache's cost and its share show in Analytics, and a miss is logged with its reason. Touches `agents/usage.py`
(`parse_model_prices`, the cache's usage lines, the cost), `agents/agent.py`, `panel/` (Analytics · Prompts),
`specification/ARCHITECTURE.md`.

**What needs to be done:**
- **The cache's own lines.** Making a cache is a usage line of kind `cache`: the model, the cached tokens
  (`cache_write_tokens`, billed at the input price) and its TTL. Each renewal is a line with the tokens and the
  seconds added. Never a text.
- **The prices.**
  - `PRICE_MODELS` takes an optional third and fourth number, `model=in/out/cache_read/storage_per_hour` — 3.1 Pro
    `2/12/0.2/4.5`.
  - The cost of a line with `cache_read_tokens` prices them at the third number. A cache line's storage is priced at
    tokens × hours × the fourth.
  - `model=in/out` keeps today's meaning.
  - The local `server/.env` gains the 3.1 Pro entry, owner-held and never printed.
- **Analytics · Prompts:** the share of prompt tokens read from the cache, by agent, model and kind, today and over
  the period, beside the prompt's length.
- **Why a call missed** (Lumi's `cache_log`): each cache made is logged as `first`, `expired` or `moved`. The log line
  names the parts whose fingerprint changed (the start, a step, the history's growth) — names only.

**Dependencies:** AGORA-256

**Expected result:**
The panel prices a cached token right and shows how much of her prompt the cache served, and her log says why a cache
was made again.

**Acceptance criteria:**
- [ ] The prices with 2 and 4 numbers; a cached read and a cache's storage priced; the share in Analytics; the miss log.
- [ ] **Tests:**
  - the price parser (old and new forms, a malformed entry);
  - the cost with cache reads and storage;
  - the cache lines valid;
  - the Analytics share;
  - the miss reasons;
  - no text in any line.
- [ ] **Contract:** `PRICE_MODELS`' form and the usage line's cache kinds in ARCHITECTURE §Contracts, pinned by
  `tests/test_usage.py` and the panel's analytics tests.
- [ ] **Gates:** lint, tests.
