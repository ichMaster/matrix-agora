## Findings

### 1. 🟠 A network error in the download kills the hearing task
`agents/matrix.py` `download`; `agents/herald.py` `_heard_voice`.

**Scenario:**
- The homeserver restarts while Hermes fetches a voice message. `client.send` raises `ClientConnectionError` (or the
  body read times out). It is not caught in `download`, nor in the spawned `_heard_voice`.
- The task ends with asyncio's "Task exception was never retrieved" traceback in the log, not a reasoned line.
- In Agora the owner's voice gets no transcript; in his room the question gets no answer, with no `hear: …` line
  saying why.

**Fix:**
- `download` catches any failure of the request or the read and returns None, logged by its type.
- `_heard_voice` is wrapped like every callback: a failure is logged, and he keeps running.

### 2. 🟡 A malformed `info` raises in `hear`
`agents/herald.py` `hear`.

**Scenario:** a client sends `"info": "x"`. The size and mimetype reads are guarded, but the duration fallback calls
`info.get` on a string.

**Fix:** `info` that is not an object is treated as empty.

### 3. 🟡 A transcript during a speaker's restart is not answered live
**Deferred → backlog:** a speaker that was down when the voice arrived never saw it, so its transcript is only
context after the backfill. The first-sync rule says nothing from before a start is answered; the owner can repeat.

### 4. 🟡 The chat's week of Agora
**Deferred → backlog:** unchanged from v5.1 review #13.

## What's solid

- **No forged owner line.** Only the roster's `transcribe` member's prefixed, non-edited reply to an owner voice the
  agent itself saw is read as the owner. Another agent, another voice or an edit stays as it is (pinned by
  `tests/test_transcripts.py`). Hermes's one Agora send builds its content in code from the owner's own words.
- **The live path works.** The owner's 4.6 s voice got its transcript in about 2 s, and Ada and Bruno answered it as
  an unnamed owner message, with the same R1 draw as typed words.
- **Secrets and texts.**
  - The Deepgram key leaves the environment at start.
  - The audio is never written or logged.
  - `stt` lines carry only the length.
  - The sentinel tests prove no transcript reaches a log.
- **Caps.** 20 MB by the event's size before any request, by `Content-Length`, and by bytes read (≤ cap + 1).
