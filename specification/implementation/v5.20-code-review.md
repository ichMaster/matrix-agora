## Findings

### 1. 🔴 The re-check command opens the backup's lines — `agents/talk.py:132`, `main`

`python -m agents.talk recheck` marks `clean` every `censored` private line that Gemini does not block in a group of
20.
- **The backup's lines.** The archive does not say which model wrote a line, so the backup's answers, and the owner's
  lines it answered, are opened too. This breaks the owner's rule of v5.15.4 and of 2026-11-02.
- **The groups.** A group of 20 that passes can still block among the 300 lines of her real prompt. The night's one-off
  run did both: 1,068 lines opened, 312 of them the backup's; 28 of them blocked her prompt by morning.

**Fix:** remove the command. ROADMAP §v5.21 already does («The re-check command (v5.20, AGORA-174) goes»), so it is
deferred there. The command runs only by hand and has not been run since the night of 2026-11-02.

### 2. 🟠 A period that keeps failing stalls the writer — `agents/agent.py` `_talk_tick` / `_talk_text`

**What happens now.** A summary call that gives `None` is told apart by one `probe`:
- a prompt-stage block halves the items;
- anything else counts as a failure, and the period stays due with a 10-minute back-off.

**Why it stalls.** `probe` answers False for an answer-stage block as well (its contract). So a period whose summary is
blocked at the answer stage, or whose request fails every time, is retried every 10 minutes for good. Each retry is a
Pro call. Because `periods_due` is oldest first, that period is always `due[0]`, so no later period is ever written.

**Fix:** count the failures per period. After `TALK_FAILS_MAX` (3) tries, write the period empty, with its items counted
as left out, so it is never asked again and the queue moves on.

### 3. 🟠 An empty coarser summary hides the finer ones — `agents/talk.py:120` `talk_section`

**What happens now.** A row is left out when a coarser row covers its start, whether or not that coarser row has text.

**Why it loses memory.** When a four-hour block is folded from its hours' summaries and Gemini blocks that request
whole, the block is written empty. Its hours (and a week's blocks, likewise) then vanish from her prompt, although
their own summaries passed. The live archive has 10 empty four-hour rows; none hides an hour yet, but the next fold of
a blocked day would.

**Fix:** only a coarser row with text hides the finer rows it covers.

### 4. 🟠 A line closed after its summary stays in it — `agents/agent.py` (the probe, the judge, hand edits)

**What happens now.** A summary is written once and never rewritten. A line closed later stays in what the summary
says, in her prompt to Gemini: by the probe, by the judge's flag, or by a hand edit (as on 2026-11-02, when the backup's
312 lines and the 28 that blocked were closed).

**Why it is deferred.** v5.21 removes the probe and the judge. After it, only a block's own lines are closed, and they
are the newest, whose hour is not yet summarized. A line deleted by hand drops its period's rows by hand, as was done on
2026-11-02 (12 rows, then 1). → v5.21; the issue that removes the probe notes it.

### 5. 🟡 A summary that overlaps the window repeats lines — `agents/talk.py:120`

`talk_section` shows the rows that **began** before the window's first line. The hour that holds that line is
summarized and also partly in the window. This costs a few words, and nothing is wrong or lost. → backlog.

### 6. 🟡 The window is read twice per prompt — `agents/agent.py` `talk_now`

`talk_now` calls `_gemini_lines()` for the window's first line, and `gemini_history_shown()` reads it again. That is one
indexed query more per private prompt. → cleanup.

## What's solid

- **What is due** is pure, with an injected clock. DST days have their true block lengths, and an hour with no open line
  is never summarized.
- **Closed lines.** The writer reads only lines open to Gemini (`private_between(gemini=True)`), and the summaries enter
  only Gemini's private prompt, never the backup's.
- **The persona rule** holds: a summary that names what she is is asked once more, then left empty.
- **The panel** opens the archive read-only (`mode=ro`), escapes every summary and prompt text, and answers `null` or
  404 rather than a 500.
- **The Prompt tab's file** is written atomically at 0600 and never logged. The log holds counts and ISO hours only.

## Fixes applied

### #2 — 88fd52a

- **The change:** `_talk_tick` counts a period's failures whose probe said the prompt passes (`_talk_probed is False`).
  After `TALK_FAILS_MAX` (3) of them, the period is written empty, its items counted in `left_out`, and the log says
  «left empty — N failures with no prompt-stage block». A failure whose probe failed too is an outage: it backs off as
  before and never counts.
- **The tests:** `tests/test_talk_writer.py::test_a_period_that_keeps_failing_unblocked_is_left_empty_and_the_next_one_is_written`
  (an answer-stage block twice tried again, then empty, then the next period written) and
  `::test_an_outage_never_leaves_a_period_empty`.

### #3 — 7f6b741

- **The change:** `talk_section` lets only a coarser row with text hide the finer rows it covers.
- **The test:** `tests/test_talk.py::test_an_empty_coarser_row_hides_nothing_so_its_hours_stay`.

**Verification:** lint clean, the full suite green after each fix; compose n/a (`server/` unchanged).
