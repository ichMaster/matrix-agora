## Findings

### 1. 🟠 Port 8090 is published on every interface and Docker bypasses ufw
`server/docker-compose.yml` — `ports: "8090:8090"` binds `0.0.0.0` **and** `[::]` (seen on the host with `ss`).
Docker inserts its own iptables rules for published ports ahead of ufw, so the ufw rule from AGORA-038 does not
filter 8090 at all. Today nothing reaches it from outside because the router forwards nothing and the host has only
a link-local IPv6 address — but one router change, a global IPv6 address or a VPN interface would expose the panel
(token-gated, but plain HTTP).
**Fix:** publish on the LAN address only — `"${PANEL_BIND:-127.0.0.1}:8090:8090"`, with `PANEL_BIND=192.168.1.197`
in `server/.env`. The default is loopback, so a missing value fails closed.

### 2. 🟠 An unexpected error kills the health-probe loop for good
`panel/health.py` `Prober.run()` — `check()` catches only `httpx.HTTPError`; anything else (a `ValueError` from a
malformed URL or response, an `OSError`, a bug) propagates out of the `while True`, the background task ends, and
nothing restarts it. The simulation card then shows the last state forever ("checked 3 h ago"), and the global status
keys off it.
**Fix:** treat any exception in one check as `unreachable` (logged with its type only), and keep the loop alive.

### 3. 🟡 The panel holds the docker socket although v3.3 only reads
Mounting `/var/run/docker.sock:ro` does not make the API read-only — a compromised panel process is root on the
host. This is the accepted PoC trade-off in ARCHITECTURE §Security.
**Defer → v3.4:** v3.4 needs actions anyway; decide there between the plain socket and a socket proxy that allows only
the endpoints the panel uses.

### 4. 🟡 Every tick re-reads all usage lines and up to 60 day files
`panel/memory.py` — at ~180 bytes per Gemini call the usage files grow a few MB a year; reading them every 10 s per
open tab is fine for the PoC, linear forever.
**Defer → backlog:** cache by file size + mtime.

### 5. 🟡 A container in a restart loop shows as "running"
`panel/docker_read.py classify()` maps docker's `restarting` to `running`.
**Defer → v3.4:** with actions in place, show it as `warn` "restarting".

### 6. 🟡 The agents' env file now also carries `PANEL_TOKEN`
`env_file: .env` gives the agent containers every variable in `server/.env`. Nothing logs the environment; the
impact of a leak is read-only panel access on the LAN.
**Defer → backlog**, together with v3.2 #3 (a separate agents env file).

### 7. 🟡 The homeserver's 8008 binds every interface too
Same mechanism as #1, outside this phase's code.
**Defer → backlog:** the same `${…_BIND}` treatment.

## What's solid

- The token gate runs before routing (constant-time), so even unknown `/api/*` paths are 401; the panel refuses to
  start without a long token; the docs routes are off; no mutating route exists (pinned by a test).
- Every name a request carries goes through the registry; docker containers are found by compose labels; the probe
  URL comes from the registry, never from a request.
- The page: all dynamic text goes through one escaper; no inline scripts; a strict CSP (`default-src 'self'`); no
  outside request — pinned by tests and verified in the browser.
- The panel container gets only `PANEL_TOKEN`, the prices and `TIMEZONE` — never the agents' keys or passwords;
  `state/`, the socket and os-release are mounted read-only; uid 1000.
- Plans' mutation tags never leave `panel/memory.py` raw; logs carry events only.
- Degrade by card works (checked in the browser with docker down); the token table equals `usage_report.py`.

## Fixes applied

- **#1 — `e752d03`:** the panel is published as `${PANEL_BIND:-127.0.0.1}:8090:8090` (unset → loopback, fails
  closed); `server/.env` and `.env.example` carry `PANEL_BIND=192.168.1.197`. Regression tests in
  `tests/test_compose.py` (the exact binding; no `0.0.0.0` / `[::]` / bare port) — fail without the fix. Redeployed;
  `ss -ltn` on the host shows only `192.168.1.197:8090` (no `0.0.0.0`, no `[::]`); the page still opens from the Mac.
- **#2 — `575116e`:** `Prober.check` turns any exception into `unreachable` (logged by type only) and `Prober.run` keeps
  looping past a crashed check. Regression test `test_an_unexpected_error_is_unreachable_and_the_loop_survives` —
  fails without the fix.
