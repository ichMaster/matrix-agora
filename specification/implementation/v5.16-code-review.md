## Findings

### 1. 🟠 A failed probe call is logged only at DEBUG — `agents/llm.py` `probe`

**Scenario:**
- The live call is 3.1 Pro with `max_output_tokens=1` and `thinking_level=LOW`, a combination no fake can vouch for.
- If the API rejects it (a `ClientError`, say), every probe returns `None` and the search stops with `error`.
- The agents log at INFO, so the owner's log shows only `probe: stopped — error (1 calls)`, never which error. The
  feature would be dead with no clue why.

**Fix:**
- log `probe: failed (<type>)` at WARNING: the type only, never a text;
- a test pins the level.

### 2. 🟠 A failed call after a found set throws the found set away — `agents/agent.py` `probe_blocked`

**Scenario:**
- Two causes. The first round finds and closes-in-waiting set A.
- The re-check of what is left (or a call in the second round) fails, so `search` returns `Found(closed=A,
  outcome="error")`, as its docstring says ("what was found before it stands").
- But `probe_blocked` closes only on `found` or `cap`. A is dropped and ten calls are spent for nothing. The same block
  comes back at the next message.

**Fix:**
- close `found.closed` whenever it is not empty, whatever the outcome;
- ARCHITECTURE's sentence says the same;
- a test: a set found, then a failing call → the set is closed.

### 3. 🟡 With the day's calls spent, nobody rates the older lines — `agents/agent.py` `_probe_after`

**Scenario:**
- `PROBE_DAY_CALLS` is used up today.
- At a prompt-stage block `_probe_after` still returns True, because it checks only that the settings are above 0.
- So `_private_text` keeps the blocked prompt's older lines from the judge, and then `probe_blocked` logs `probe: off`.
- Neither rates them, against the rule that with the probe off the judge rates them as in v5.15.

**Fix:**
- `_probe_after` reads today's `probed` calls from the route file and returns False when nothing is left;
- a test: spent → the judge gets the older lines and no probe is spawned.

### 4. 🟡 The window's-end paths with the probe are untested — `tests/test_probe_route.py`

**Scenario:** the probe is wired into three places (the route `gemini`, the window's end with the judge, the window's end
without it), but only the first is tested. A slip in the other two (no `parts` passed, the judge's share left as
before) would go unnoticed.

**Fix:** tests for both window's-end paths: a prompt-stage block there spawns the probe once her line is sent, and with
the judge, the judge gets only his line and her answer.

### 5. 🟡 A found set is never tried alone — `agents/probe.py` `_minimal` (DEFER → backlog)

**Scenario:**
- QuickXplain counts on the filter blocking more as more is added, and on its verdicts being stable.
- Its result is derived, not tested on its own.
- If Gemini's prompt filter is flaky (a benign subset "blocked" once), an innocent part could be closed.

**Why defer:** the re-check of what is left already guards a little, and one more call per round costs budget. The live
logs (`closed N …` against whether the same block returns) will show whether the filter is stable. Revisit with data.

### 6. 🟡 «Agora today» is a fixed layer (DEFER → backlog)

**Scenario:**
- A line said in Agora today that Gemini blocks sits in «Agora today» (`agora_now`).
- The probe names the layer `agora_now` and closes nothing.
- Every private answer that day is blocked again and probed again, within the day cap.

**Why defer:** ROADMAP §v5.16 lists «Agora today» as fixed. Making its lines closable items (`line:<key>`, they are
archive lines) is a small follow-up, but it changes what the owner agreed.

### 7. 🟡 Calls counted only at the end (DEFER → backlog)

**Scenario:** `route_step("probed", …)` runs after `search` returns. An exception in `render` or a restart mid-search
leaves its calls uncounted toward `PROBE_DAY_CALLS`.

**Why defer:** the probe runs rarely, the counter is a soft cap, and counting per call would write the route file a dozen
times per probe.

## What's solid

- **The search is ids only, with an injected oracle.**
  - No text enters it.
  - Its outcomes are distinct and logged by name.
  - It never closes all that is left.
  - QuickXplain finds one cause among 40 within 12 calls, and a pair within 15–19.
- **The prompt in parts is drawn whole as the prompt sent** (byte for byte, and equal to the old `build_prompt` path).
  What the probe sees is what Gemini blocked.
- **Off the reply path:**
  - the probe is spawned in `private_reply`'s `finally`, after her line is sent;
  - it runs behind its own lock;
  - an exception is logged by type.
- **Closing only ever closes.**
  - `censored` drops the vector and takes a private line out of Gemini's history; the fact mirror follows.
  - The judge's fresh-mark rule (v5.15.5) keeps a line the probe closed from being reopened by a late verdict.
- **The caps:**
  - per block, and per day in the route file (survives a restart, resets with her day);
  - 0 turns the probe off, and the judge rates as in v5.15.
- **Logs** hold counts, outcomes and layer names, never a key or a text.
