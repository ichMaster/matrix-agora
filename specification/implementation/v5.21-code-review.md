## Findings

### 1. 🟠 An echoed `[селфі: ...]` is cut in silence — `agents/photo.py:105`, `agents/agent.py:1067`

**Failure scenario:** since 024a03b every photo of hers is kept in her history as `…\n[селфі: ...]`. Gemini has
echoed her kept note before (v5.17 review #2), and now the form it would echo is `[селфі: ...]`: «Ось, лови 🙂
[селфі: ...]». `split_photo` cuts the note and, its description being only dots, names no shot; `private_reply`
sees no shot and sends «Ось, лови 🙂» with nothing — the «дивись» with nothing that v5.17 forbids. The same was
already true of an empty marker line («СЕЛФІ:» with nothing after it), now far likelier.

**Fix:** a marker or note that names nothing gives `Shot(kind, "")` (a described one later in the line still wins);
`private_reply` treats a shot with no description as a photo that did not come out: logged `photo: dropped (no
description)`, her answer drawn once more without the skill and with `PHOTO_FAILED`, as for a blocked photo.

### 2. 🟠 A stale setting cannot be cleared — `panel/settings.py:99`, `panel/settings.py:108`

**Failure scenario:** v5.21 removed `PROBE_CALLS` and `PROBE_DAY_CALLS`; Кіра's overrides of them stay in
`state/settings.json`. Each of her starts logs `settings: ignored PROBE_CALLS, PROBE_DAY_CALLS`, the panel never shows
them, and a `reset` of either is refused with 422 («unknown setting»). Only a hand edit on the host — which the rules
forbid — would clear them. Live since 07:58 on 2026-11-02.

**Fix:** a save drops the scope's stored names the schema no longer knows (reported as saved, restarting nobody), and
a `reset` of such a stored name is accepted.

### 3. 🟡 A summary keeps a line closed later — `agents/agent.py:1337`

**Failure scenario:** `mark_unanswered` closes his unanswered lines; when he wrote across an hour's end and that hour's
summary was already written, the summary keeps what is now `blocked`. Hand closes (as on 2026-11-02) do the same.

**Fix (later):** when a line is made `blocked`, drop the talk rows whose period holds it, so the writer redoes them. On
2026-11-02 the 6 summaries over the hand-closed lines were dropped and rewritten by hand.

### 4. 🟡 The `blocked` count includes the emptied rows — `panel/memory.py:280`

The count is right as a count of closed rows, but the panel shows no split between the ones that still hold a text and
the emptied ones. A second number would do.

### 5. 🟡 The migrated facts' age — `agents/facts.py:230`

`migrate_marks` rewrote the 9 files, so their mtime is the migration's. The emptying reads the age from the mtime, so
they go a day after 2026-11-02 07:58 rather than at once. One-time; nothing to change.

### 6. 🟡 The prune is host-wide — `server/deploy.sh:99`

`docker image prune -f` removes every untagged image no container uses, other projects' too (Lumi, RoboFace). Such an
image has no name to run by, so nothing is lost; a label filter would keep the step to this project.

## What's solid

- **The marks:** `Archive.mark()` and `set_mark()` never touch a `blocked` row or fact and never open a closed one;
  the migration is one-way at `user_version` 2 and logged by counts.
- **The route:** `step`, `mode`, `backup_mark` and `route_status` are pure over plain data with the clock injected; the
  hour's count resets on `/gemini`; a block under `/backup` is neither counted nor windowed.
- **The emptying:** idempotent, keeps the row and its key so a Matrix re-seed cannot bring a line back open; `/purge`
  shares it.
- **The backup:** never keeps a fact, recalls by words only (its query never goes to Gemini's embeddings), skips the
  emptied lines.
- **The day itself:** blocks, the 5-minute window, `/gemini` and the hour's count worked live on 2026-11-02.
