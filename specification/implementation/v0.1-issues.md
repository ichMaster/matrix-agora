### AGORA-002 — Bring up the homeserver on the Ubuntu host

**Description:**
Owner-run: install Docker on the Ubuntu box, place the AGORA-001 files at `~/matrix-agora/server/`,
generate the registration token, open the LAN firewall rule and start the container. The scripted deploy
arrives only in v0.2, so this one bring-up is by hand.

**What needs to be done (owner, on 192.168.1.197):**
- Install Docker Engine + the compose plugin from Docker's official Ubuntu repository.
- `mkdir -p ~/matrix-agora/server` and copy `server/docker-compose.yml` there (e.g. `scp` from the Mac).
- Create `~/matrix-agora/server/.env` with `REGISTRATION_TOKEN=$(openssl rand -hex 24)`.
- `sudo ufw allow from 192.168.1.0/24 to any port 8008 proto tcp`.
- `cd ~/matrix-agora/server && docker compose up -d`, then check `docker compose logs -f homeserver`.
- `sudo reboot`, confirm the container comes back on its own.

**Dependencies:** AGORA-001

**Expected result:**
The homeserver answers on `http://192.168.1.197:8008` from the LAN only and restarts with the host.

**Acceptance criteria:**
- [ ] `curl http://192.168.1.197:8008/_matrix/client/versions` from the Mac returns JSON with a list of versions *(Claude can run this read-only check)*
- [ ] `curl http://192.168.1.197:8008/_matrix/federation/v1/version` does not respond as a federation endpoint *(Claude can run this read-only check)*
- [ ] **Manual (owner):** after `sudo reboot` the container comes back up on its own
- [ ] **Manual (owner):** the ufw rule limits :8008 to `192.168.1.0/24`; no router port-forward exists
- [ ] **Gates:** n/a (no repo code changes; the token never enters the repo)
