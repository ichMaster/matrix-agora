# v7.1 — Issues

Issues for phase **v7.1 — The Claude engine for a persona: answers on Sonnet, the background on Haiku** (version
**v7 — Claude for everyone: every agent on the owner's subscription**), derived from the Tasks and DoD in
[ROADMAP.md](../ROADMAP.md) §v7.1 and the contracts in [ARCHITECTURE.md](../ARCHITECTURE.md). This file covers one
phase; ids continue from the previous phase (AGORA-237 → **AGORA-238…241**).

The phase gives a persona, the cat and Hermes a second engine: one line of the TOML, `engine = "claude-sdk"`, moves
every one of their language-model calls to Claude through the Agent SDK on the owner's subscription — answers on
Sonnet, the background on Haiku — while an agent left on `gemini` stays exactly as it is. It builds on v4.4's
`ClaudeSdkResponder` (`agents/claude_sdk.py`: the subscription's layers, the limit, the status file) and on the
`GeminiClient` surface every caller uses (`agents/llm.py`). No service moves yet: the room moves in v7.2, Устина in
v7.3, Кіра in v7.4.

## v7.1 — The Claude engine for a persona

### AGORA-238 — The Claude client: `GeminiClient`'s calls over the Agent SDK

**Description:**
A `ClaudeClient` in `agents/claude_sdk.py` (layer 6: the SDK is imported there and nowhere else) with the methods the
agent and the herald call on `self.llm` — `generate`, `complete`, `reply`, `think`, `search`, `embed`, `probe` — each a
stateless `query()` on the subscription. The init check, the limit handling and the status file are shared with
`ClaudeSdkResponder`, whose behaviour stays as it is.

**What needs to be done:**
- One stateless `query()` per call: the instruction as the system prompt (a plain string, so the CLI's own prompt is
  replaced), the transcript as the prompt, `setting_sources=[]`, no MCP servers (`strict_mcp_config`), one turn, no
  tools, thinking off (`{"type": "disabled"}` — the closest to Gemini Flash's `thinking_budget=0`), the call's
  `max_output_tokens` as `CLAUDE_CODE_MAX_OUTPUT_TOKENS`, no session persistence, the tmpfs config dir — the options
  built by one pure function beside `sdk_options`.
- The model by the call's kind, never by the Gemini model a caller names (`think(model=…)`, `complete(model=…)` are
  ignored): the agent's voice — `VOICE_KINDS` = the answers (`reply`, `private`, `private_nudge`) and Hermes's
  writing (`digest_voice`, `ask`) — on `reply_model` (`CLAUDE_REPLY_MODEL`, default `sonnet`), every other kind on
  `background_model` (`CLAUDE_BACKGROUND_MODEL`, default `haiku`). `reply_model` and `model` are attributes as on
  `GeminiClient`, so `keep_prompt` and the logs name them; neither is in `THINKING_MODELS`, so no Pro-only path runs.
- `search(question, max_output_tokens, kind)`: the toolset `search` — `WebSearch` alone (tools, allowed tools and the
  init check's allowed list), a few turns, on the background model; the answer's text only.
- `embed(texts, task, kind)` goes to the Gemini client handed in (`embedder`), or returns None without one; `probe`
  returns None (the scan stops as on a failed check — the scan on Claude is v7.3's), logged once.
- Each call bounded: `REPLY_TIMEOUT_S` for an answer kind, `THINK_TIMEOUT_S` for any other (`agents/llm.py`), tried
  once more when it hangs, as `GeminiClient._within`; at most `concurrency` (`CLAUDE_CONCURRENCY`, default 2) CLI
  processes at once per container (an `asyncio.Semaphore`).
- The init check as v4.4's layer 5: `apiKeySource == "none"`, no tool but `WebSearch` on a `search` call, no MCP
  server — a wrong auth source blocks every later call until restarted; a wrong tool list refuses that call.
- The limit as v4.4's layer 7, kept per agent in `state/<name>.ratelimit.json` (`ClaudeStatus`): `allowed_warning`
  mutes for `WARN_MUTE_S`, `rejected` until `resets_at`, a 429 result mutes, an overage answer is never used. While
  muted, `limit_fallback` decides (decision 1): `gemini` — the same method on the `GeminiClient` handed in
  (`fallback`), its usage lines Gemini's own; `silent` — None with a log line, as Claude.
- A decline — the result's `stop_reason == "refusal"`, or for an answer (`reply`, `complete(refusal=True)`) a
  `refusal_marker` in the text — returns None, sets `LAST_BLOCK` to `("refusal", reason, None)` (reason `stop` or the
  matched phrase, never the text) and logs `claude declined: reason=… kind=… model=…`.
- One usage line per call through the sink (`record_sdk_usage`): the kind, the model id the CLI reports
  (`model_usage`'s key) or else the alias, `ok`, the tokens, `latency_ms`, `blocked="refusal"` on a decline
  (`sdk_usage_line` gains `blocked`); always `claude-sdk` / `subscription`. Never a text in a log or a file.

**Dependencies:** None

**Expected result:**
Every call an agent makes on `self.llm` has a Claude path on the subscription, on the model its kind asks for.

**Acceptance criteria:**
- [ ] `generate`/`complete`/`reply`/`think`/`search` return what `GeminiClient`'s do (`str`, `(text, finish)` with
  `max_tokens` from the stop reason, or None); `embed` delegates; `probe` is None.
- [ ] **Tests:** `tests/test_claude_client.py` against a fake `query`/options (no SDK, no network): every call kind on
  its model; the options (no tools, thinking off, the cap, no settings; `search` with `WebSearch` alone); the timeout
  and the second try; the semaphore's bound; `is_error` and a 429; `RateLimitEvent` → the status file and the mute;
  both `limit_fallback` values; the init check (an API key source blocks, an extra tool refuses); a refusal stop and a
  refusal marker → None and `LAST_BLOCK`; the usage line (model id, `blocked`, `latency_ms`, `subscription`);
  `embed` on the embedder. `tests/test_claude_sdk.py` unchanged and passing.
- [ ] **Contract:** the usage line's `blocked` on a `claude-sdk` record — `tests/test_usage.py` and ARCHITECTURE.md
  §Token accounting.
- [ ] **Gates:** lint, tests.

### AGORA-239 — The engine per agent: a persona, the cat or Hermes on Claude

**Description:**
The TOML's `engine = "claude-sdk"` on a `persona`, the `creature` or the `herald` gives that agent a `ClaudeClient` as
its `self.llm` and a responder over it (`agents/responder.py`), in `agents/agent.py` and `agents/herald.py`; the
`assistant` keeps `ClaudeSdkResponder` exactly as since v4.4.

**What needs to be done:**
- `agents/agent.py`: `claude-sdk` on the assistant — as before; on any other type — `check_startup` and `scrub` as
  Claude's, then the client from the agent's settings (`CLAUDE_REPLY_MODEL`, `CLAUDE_BACKGROUND_MODEL`,
  `CLAUDE_CONCURRENCY`, `CLAUDE_LIMIT_FALLBACK`), its status file `state/<name>.ratelimit.json`, `record_sdk_usage` as
  its sink. A `GeminiClient` is built beside it only when needed — `recall` (the embeddings) or
  `CLAUDE_LIMIT_FALLBACK=gemini` — and only with `GEMINI_API_KEY` set (else a WARNING: no recall's meaning search /
  silent at the limit).
- The CLI inherits no secret but the OAuth token: before the first call, `GEMINI_API_KEY` (handed to `GeminiClient`
  as `api_key`, a new optional argument), every `*_PASSWORD` (the agent's own is read by `load_config` first),
  `REGISTRATION_TOKEN` and `PANEL_TOKEN` leave the environment — a pure `secret_vars(env)` in `agents/claude_sdk.py`
  beside `forbidden_vars`. The keys already taken out at start (ElevenLabs, Telegram, Deepgram, NovelAI, fal, the
  Guardian) stay so.
- `agents/responder.py`: `responder_for("claude-sdk", llm)` gives the same kind routing as `GeminiResponder` (an
  answer kind through `reply`, any other through `complete`) — one responder for both clients; the persona's rules
  stay where they are (`_compose`: `PASS`, `clean_reply`, `cut_openings`, the cat's word cap, `outs_a_persona`).
- `agents/herald.py`: Hermes on `claude-sdk` the same way — his `think` calls (`digest_voice`, `ask`) on the reply
  model; his hearing on Deepgram as before.
- A decline in Agora is silence, its reason in the log (AGORA-238's line); the private chat keeps its Gemini-shaped
  route until v7.3 (a decline there leaves `LAST_BLOCK` set, as a refusal does today).
- `agents/roster.py`: `claude-sdk` stays allowed on every type; a test pins it on a persona, the creature and the
  herald.
- ARCHITECTURE.md §Components (the engine per agent: Claude as itself, or the Claude client for every other type) and
  §Contracts (the TOML's `engine` on any type).

**Dependencies:** AGORA-238

**Expected result:**
Switching a member's TOML to `claude-sdk` moves all its calls to Claude; nothing changes for a member on `gemini`.

**Acceptance criteria:**
- [ ] With `engine = "gemini"` every agent's prompts and calls are as before (the existing tests pass unchanged).
- [ ] An agent on Claude: its replies, summaries, day memories, plans, today block, events, mood, sky (`search`) and
  Hermes's digest go through the client on their models; `embed` on Gemini for an agent with `recall`.
- [ ] **Tests:** in `tests/test_claude_engine.py` (nio mocked, a fake client): a persona, the cat and Hermes built
  with `claude-sdk` get the Claude client and the Claude responder; Claude himself still gets `ClaudeSdkResponder`; a
  forbidden variable refuses the start; `secret_vars` names the passwords, `GEMINI_API_KEY`, `REGISTRATION_TOKEN`
  and `PANEL_TOKEN` and never `CLAUDE_CODE_OAUTH_TOKEN`; after start none of them is in `os.environ`; the Gemini
  client is built for `recall` or the fallback only; a decline in Agora is silence. `tests/test_roster.py`: the

- [ ] **Contract:** the TOML's `engine` — `tests/test_roster.py` and ARCHITECTURE.md §Contracts.
- [ ] **Gates:** lint, tests.
