## v5.7 — Кіра in Telegram

### AGORA-106 — The Bot API client and its state: `agents/telegram.py`

**Description:**
A small Telegram Bot API client over `aiohttp` (already a dependency; no new one), its pure parts, and the offset
state `state/<name>.telegram.json`. Touches `agents/telegram.py` (new), `tests/test_telegram.py` (new) and
ARCHITECTURE §Data and state files.

**What needs to be done:**
- The pure parts:
  - `parse_update(raw) -> Update | None`: `update_id`, the sender's numeric id, the chat id and type, the date (ms),
    and the kind: `text` (with its text), `voice` (its `file_id`, `duration`, `mime_type`, `file_size`) or `other`.
    `edited_message`, `channel_post` and every other update type are `other`. Malformed → `None`.
  - `allowed(update, owner_id) -> Verdict`: only a private chat (`chat.type == "private"`) whose sender is the
    owner's numeric id; everything else is refused with a reason (`stranger`, `not-private`, `unsupported`). The
    log names the reason and the update kind only, never an id or a word.
  - `next_offset(updates, offset)`: the highest `update_id` + 1.
- The state: `TelegramState` (`offset`), `load_telegram_state` / `save_telegram_state`, atomic (temp file + rename)
  and 0600 from birth, as `agents/private.py`'s. A missing or corrupt file is a fresh state.
- The client `TelegramBot(token)`:
  - `get_updates(offset, timeout_s)` (long polling, `allowed_updates=["message"]`), `send_message(chat_id, text)`
    (plain text, no `parse_mode`; a text over 4,096 characters is cut at a sentence), `send_voice(chat_id, ogg,
    duration_s)` (multipart, `voice` as `audio/ogg`), `send_chat_action(chat_id, action)` (`typing`,
    `record_voice`), `get_file(file_id)` and `download(file_path, max_bytes)` (capped; over the cap → `None`,
    never read);
  - every failure returns `None` / `False` and is logged by its HTTP status, Telegram's `error_code`, or the
    exception's type. **The token is never logged**: it is part of every URL, so no URL, `repr` or exception text
    reaches a log.
  - `retry_after` (HTTP 429) is honoured by the caller, so it is returned, not slept here.
- ARCHITECTURE §Data and state files: the row for `state/<name>.telegram.json` (v5.7, a person with `telegram`):
  `offset` — no text, no token, no id; atomic, 0600; a corrupt file starts fresh.

**Dependencies:** None

**Expected result:**
A tested Bot API client and its offset state, used by nothing yet.

**Acceptance criteria:**
- [ ] `parse_update` handles text, voice, edited messages, other update types and malformed input.
- [ ] `allowed` lets through only the owner's private chat; a stranger, a group and an unsupported kind are refused
      by reason.
- [ ] The offset survives a save and load, a corrupt file starts fresh, and the file is 0600.
- [ ] **Tests:** `tests/test_telegram.py` with aiohttp mocked: the parsing, the allowlist, the offset across a
      restart, `send_voice`'s multipart content (the `voice` part, `audio/ogg`, the duration), `send_message`'s
      plain text and the 4,096 cut, the download cap, every error path returning `None`/`False`; and no token,
      id or text in any captured log line.
- [ ] **Contract:** the state file `state/<name>.telegram.json` in ARCHITECTURE §Data and state files, pinned by
      `tests/test_telegram.py`.
- [ ] **Gates:** lint, tests.

### AGORA-108 — One private chat, two channels: the poller, voice both ways, `last_channel`

**Description:**
Кіра's process polls her bot beside the Matrix sync, and the v5.6 private path serves both channels: one history,
one memory, the answer back to the channel it came from, voice both ways. Touches `agents/agent.py`,
`agents/private.py`, `tests/test_private.py` (or a new `tests/test_telegram_runtime.py`) and ARCHITECTURE
§Message flow and §Data and state files.

**What needs to be done:**
- **Start-up** (only with `telegram`):
  - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_ID` and `DEEPGRAM_API_KEY` leave the environment at start (`os.environ.pop`,
    as the ElevenLabs key). Without the token or the owner's id → `telegram off: no <VAR>` and she runs without
    it; without Deepgram's key → `telegram: hearing off` (a voice note then gets a short text answer that she could
    not listen to it, from a fixed line, no model call).
  - The poller is one task beside `sync_forever`, cancelled on shutdown with the others.
- **The poller:**
  - long polling (`timeout` 30 s) from the stored offset; the offset is saved after every batch, so an update is
    never answered twice;
  - **the first-sync rule for Telegram** — the owner's updates dated before this start are read into the private
    history as context and never answered (as the Element private room's backlog, read by `start_private`), then
    confirmed; on the very first start (no state file) the same holds for the whole backlog;
  - a refused update is logged `ignored: <reason> (telegram)` by kind; an edit is `ignored: edit (telegram)`;
  - errors: 429 → wait `retry_after`; 401/404 (a wrong or revoked token) → `telegram off: refused (HTTP n)` and
    the poller stops; 409 (another poller or a webhook) and network errors → back off (5 s doubling to 5 min) and
    retry. The bot keeps running in Agora and Element through all of it.
- **One private chat, two channels** (`matrix` / `telegram`):
  - the owner's line from either channel goes through the same path as `on_private`: the shared `private_history`,
    the session line labelled «Ich (наодинці)», the pending answer and its coalescing;
  - the answer goes back to the channel of the owner's latest message (a pending answer that gets a newer message
    from the other channel answers there);
  - `last_channel` in `state/<name>.private.json` (`PrivateState` gains it; `matrix` by default; written when the
    owner writes, never a text): writing first (`maybe_private_nudge`) goes to it;
  - the usage kinds stay `private` and `private_nudge`.
- **Telegram's side of an answer:**
  - `record_voice` (or `typing` when the line goes as text) while she composes, repeated every 4 s until sent;
  - **every answer is a voice note, then the text** (the owner, 2026-10-21): her own TTS (`VOICE_ID` =
    `KIRA_VOICE_ID`) → OGG/Opus (`encode_opus`) → `send_voice`, then `send_message` with the same text. The
    speakers' monthly cap and `voiceable` still apply; when the voice cannot be made the text goes alone, logged
    `voice: text only (<why>)` as in Matrix. The `tts` usage line as today.
- **Hearing a voice note:** `get_file` → `download` (capped at Hermes's `TRANSCRIBE_MAX_BYTES`, never written to
  disk) → `DeepgramSTT.transcribe(audio, "audio/ogg")` → an `stt` usage line (`stt_usage_line`, the audio's
  length) → the transcript is the owner's line in the private path. Nothing heard → a short fixed text answer that
  she did not catch it. An answer to a voice note is always voiced (when it can be).
- **Logs** never carry a word, the token or the owner's id: `telegram: answered`, `telegram: heard (N ms)`,
  `telegram: wrote first`.
- ARCHITECTURE:
  - §Message flow, the private chat: its two channels, the Telegram allowlist (the owner's numeric id, a private
    chat), the first-sync rule for Telegram, the answer back to its channel, writing first to `last_channel`;
  - §Data and state files: `state/<name>.private.json` gains `last_channel`.
- `specification/history/` is not touched.

**Dependencies:** AGORA-106, AGORA-107

**Expected result:**
With her bot's token and the owner's id set, Кіра answers the owner in Telegram in voice and text, hears his voice
notes, and it is one conversation with the Element private chat.

**Acceptance criteria:**
- [ ] A Telegram text from the owner is answered in Telegram (a voice note, then the text); a stranger's is ignored
      by reason.
- [ ] A voice note is heard (Deepgram mocked), an `stt` line is written, and the answer is voiced.
- [ ] One history: a Telegram line is in the private history and the session (labelled «наодинці»); an Element
      private line is in the Telegram answer's context, and back.
- [ ] Writing first goes to `last_channel`; `last_channel` survives a restart.
- [ ] Updates dated before the start are context, never answered; a restart never answers an update twice.
- [ ] A refused token stops only the poller; 429 waits; network errors back off; Agora and Element keep working.
- [ ] **Tests:** with aiohttp, Deepgram and ElevenLabs mocked and the clock injected: the routing of an answer back
      to its channel and the coalescing across channels; writing first to the last channel; `send_voice` then
      `send_message`, the note synthesised by her own TTS with her voice id; a voice note heard and answered in
      voice; the before-start backlog as context only; the error handling; the keys popped from the environment;
      no token, id or text in a log.
- [ ] **Contract:** `state/<name>.private.json`'s `last_channel` — ARCHITECTURE §Data and state files, pinned by
      `tests/test_private.py`.
- [ ] **Gates:** lint, tests.
