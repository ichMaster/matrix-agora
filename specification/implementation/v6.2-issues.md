# v6.2 — Issues

Issues for phase **v6.2 — The code for a second companion: everything Кіра has, by her TOML alone** (version **v6 —
Устина: a second companion on Кіра's code**), derived from the Tasks and DoD in [ROADMAP.md](../ROADMAP.md) §v6.2 and
the contracts in [ARCHITECTURE.md](../ARCHITECTURE.md). This file covers one phase; ids continue from the previous phase
(AGORA-217 → **AGORA-218…222**).

The capabilities are per TOML since v4.1, and the state, the settings and the panel's views are already per agent
(`state/<name>.*`, `state/<name>.settings.json`, the panel's tabs by capability). What still names Кіра or assumes one
companion is small: the main face photo (`agents/photo.py` `MAIN_FACE = "kira.png"`), the selfie line (`SELFIE`: «She
is 23, Ukrainian. She never wears makeup»), `server/deploy.sh` syncing `server/kira.env` alone, and `python -m
agents.facts seed` defaulting to Кіра. This phase fixes those and proves two companions side by side in tests; her
TOML, accounts, compose service and the rest of her canon are v6.3, Agora v6.4.

**Reconciled with the code (2026-11-07).** The ROADMAP's «the look … from her TOML» becomes a private canon file,
`agents/canon/<localpart>.look.md`: the TOML is committed to a public repo, and her look (eye colour, figure, how she
dresses) is canon, which is private (CLAUDE.md, «The canon is private»). The age comes from the natal file the TOML
already names (`natal`), so Кіра's selfie keeps «She is 23» (her chart gives 23 on 2026-11-07).

### AGORA-218 — Her photos by her name: the main face, the selfie's age and her look

**Description:**
A selfie (and a кружечок's first frame, which is a selfie) is drawn for the person whose face folder it is, not for
Кіра: `agents/photo.py` (`MAIN_FACE`, `pick_faces`, `SELFIE`, `photo_request`, `PhotoMaker`, `photo_maker`),
`agents/agent.py` (where the maker is built), ARCHITECTURE §Canon and §Contracts (the canon layout).

**What needs to be done:**
- The main face photo is `<localpart>.png` in `agents/canon/<localpart>.face/`: `pick_faces(faces, rng, main)` takes the
  main photo's name (`kira.png` for Кіра, `ustyna.png` for Устина), else the first file as now; `MAIN_FACE` goes.
- The selfie line is built per person (pure): the fixed head («the same person as in the reference photos: keep her
  face, hair and features exactly»), her age on the shot's date from her natal file's birth date
  (`agents.mood.parse_birth_date`; no natal or no date: no age), her look (the lines of
  `agents/canon/<localpart>.look.md`, English, for the image model; a missing or empty file: none), and the fixed tail
  (what suits the weather and the scene, never the reference photos' clothes).
- The private canon (gitignored; written on the Mac, synced by the deploy, never quoted in the repo):
  `kira.look.md` carries what `SELFIE` says today («Ukrainian», never makeup), so her selfie is unchanged;
  `ustyna.look.md` carries the owner's choices of 2026-11-07 (her eyes light grey in any light, never dark; no makeup;
  no jewelry; her figure and how she dresses) — read from v6.3, when she runs.
- ARCHITECTURE §Canon: the main face photo by localpart and the look file; §Contracts: the canon layout gains
  `<localpart>.look.md`. The module docstring drops `kira.png`.

**Dependencies:** None

**Expected result:**
Each companion's selfie carries her own main face, age and look; Кіра's request is the same as before.

**Acceptance criteria:**
- [ ] `pick_faces` puts the named main photo first, and the first file when it is missing; a folder of another person
  never yields `kira.png` first.
- [ ] The selfie line holds her age from her birth date on the shot's date (a birthday tomorrow keeps today's age) and
  her look file's lines; without a natal date or a look file, neither — never a crash.
- [ ] Кіра's selfie request, with `kira.look.md` as written, says «She is 23» and that she never wears makeup.
- [ ] **Tests:** `pick_faces` by name; the selfie line's age (before, on and after a birthday) and look (present, missing,
  empty); `photo_request` for a selfie and for a photo (a photo never carries the look); the maker built with the
  person's localpart; the image model mocked; a `canon`-marked test that `kira.look.md` and `ustyna.look.md` exist and
  name no model or bot (`BANNED_RE`).
- [ ] **Contract:** the canon layout (`<localpart>.face/`'s main photo `<localpart>.png`, `<localpart>.look.md`) in
  ARCHITECTURE §Contracts, pinned by the tests above.
- [ ] **Gates:** lint, tests.

### AGORA-219 — The deploy syncs every member's env file; her env example

**Description:**
`server/deploy.sh` syncs `claude.env`, `hermes.env` and `kira.env` by name; a second companion's `server/ustyna.env`
would never reach the host. `server/deploy.sh`, `server/ustyna.env.example`, `tests/test_compose.py`, ARCHITECTURE
§Configuration and secrets, §Security and access.

**What needs to be done:**
- One loop over the members: for each `agents/<name>.toml`, if `server/<name>.env` exists, rsync it to the host as
  `server/<name>.env` and `chmod 600` it there; the per-name blocks for `claude.env`, `hermes.env` and `kira.env` go.
  `voice.env` (not a member's) stays as it is. Never printed: rsync's `-i` lists the file name only.
- `server/ustyna.env.example`: the keys of `kira.env.example` (her bot's token, the owner's Telegram id, Deepgram, her
  reply model, the door, the voice, the Guardian, NovelAI, fal), each documented, no values.
- ARCHITECTURE §Configuration and secrets and §Security: a member's own env file is `server/<name>.env`, 0600, read by
  her service alone (her service and its `env_file` come in v6.3).

**Dependencies:** None

**Expected result:**
Any member's env file the Mac holds reaches the host 0600 without a line of the deploy naming her.

**Acceptance criteria:**
- [ ] `deploy.sh` names no member's env file; it syncs `server/<name>.env` for every `agents/<name>.toml` that has one.
- [ ] `server/ustyna.env.example` has the same keys as `server/kira.env.example`.
- [ ] **Tests:** the deploy's text loops over the members' TOMLs and chmods what it syncs 600 (as the existing
  `test_compose.py` checks read it); the two examples' keys equal; no example holds a value.
- [ ] **Gates:** lint, tests, compose.
- [ ] **Manual (owner):** `server/deploy.sh --dry-run` lists `kira.env`, `claude.env` and `hermes.env` as before, never
  their contents.
