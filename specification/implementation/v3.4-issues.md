## v3.4 — The panel: control

### AGORA-039 — The supervisor's actions: start / stop / restart behind POST routes

**Description:**
The write side of the supervisor and its routes. Touches `panel/actions.py`, `panel/docker_read.py`,
`panel/app.py`, ARCHITECTURE, tests.

**What needs to be done:**
- `panel/actions.py` — `Supervisor` behind two seams (fakes in tests): the docker client (stop / restart an existing
  container by its compose labels) and a compose runner (`docker compose -p <project> -f <file> up -d --no-deps
  <service>` as a fixed argv list — the service name comes only from the registry):
  - **start** = compose `up -d --no-deps <service>` (creates the container when it does not exist yet);
  - **stop** = `container.stop(timeout=30)` (SIGTERM → the session summary → SIGKILL after 30 s);
  - **restart** = stop (30 s) + compose up.
- One action at a time per target: a second action on a busy target → 409; docker unreachable → 503; a stop on a
  missing container → 409.
- Routes, `POST` only, token-gated, and **same-origin** (an `Origin` header, when present, must match the panel's own
  host, else 403): `POST /api/agents/{name}/start|stop|restart`,
  `POST /api/simulations/{id}/services/{service}/start|stop|restart`. Unknown names → 404; unknown action → 404.
  The result: `{ok, state}` with the container state after the action.
- Every action is logged as an event: who (the panel), what, target, result, duration — no tokens.
- Deferred from v3.3 review #5: docker's `restarting` becomes its own state (`warn` "restarting"), not "running".
- **Contract:** the panel API surface gains the `POST` actions — ARCHITECTURE §The panel / §Contracts updated;
  pinned by tests.

**Dependencies:** None

**Expected result:**
The API starts, stops and restarts the registry's agents and services, creating a missing container on start.

**Acceptance criteria:**
- [ ] start creates a missing container through compose; stop waits up to 30 s; restart = stop + start
- [ ] 409 on a busy target or stopping a missing one; 503 with docker unreachable; 403 cross-origin; 401 without the token; 404 on unknown names
- [ ] **Tests:** the supervisor against a fake docker client and a recording compose runner (start / stop / restart, creation on first start, the exact argv, timeout → kill semantics via `stop(timeout=30)`, busy → 409), the routes via TestClient (POST-only, token, Origin, 404s), `restarting` → its own state
- [ ] **Contract:** the POST surface — ARCHITECTURE updated, tests pin it
- [ ] **Gates:** lint, tests

### AGORA-040 — Forget the last session — stopped agents only

**Description:**
`POST /api/agents/{name}/forget` deletes `state/<name>.memory.md`. Touches `panel/actions.py`, `panel/app.py`,
tests.

**What needs to be done:**
- Allowed only when the agent's container is **stopped** or **missing**; running / restarting / unknown → 409
  ("Stopped agents only"). The path is built only from the registry name + the fixed pattern; the day memories,
  plans and everything else stay. A missing summary is not an error (`{ok: true, forgotten: false}`).
- Logged as an event.

**Dependencies:** AGORA-039

**Expected result:**
A stopped agent's last-session summary can be deleted from the panel; nothing else can.

**Acceptance criteria:**
- [ ] forget deletes only `state/<name>.memory.md`, only for a stopped / missing agent
- [ ] **Tests:** gating by state (running / unknown → 409), the exact file removed and nothing else (a fixture `state/`), the missing-file case, POST-only + token + Origin
- [ ] **Gates:** lint, tests

### AGORA-041 — The panel image and service can run compose

**Description:**
Creating a missing container needs compose with the real project — the same file and env the deploy uses. Touches
`panel/Dockerfile`, `server/docker-compose.yml`, `server/.env.example`, ARCHITECTURE, tests.

**What needs to be done:**
- `panel/Dockerfile`: the docker CLI and the compose plugin copied from the official images (`docker:*-cli`,
  `docker/compose-bin`), `DOCKER_CONFIG` in a writable place.
- The `panel` service: the stack directory mounted **at its host path** (`${STACK_DIR}/server:${STACK_DIR}/server:ro`)
  so compose resolves `../state` to the real host paths; `STACK_DIR` and `COMPOSE_PROJECT=server` in its
  environment; `state/` now read-write (forget); the docker socket as before.
- Security note in ARCHITECTURE: the panel now reads `server/.env` (compose needs it) — it already holds the docker
  socket (root-equivalent), so this widens nothing; v3.3 review #3 is decided here: **the plain socket stays** (compose
  needs create / network / volume calls a narrow proxy would have to allow anyway).
- `server/.env.example`: `STACK_DIR=/home/ich/matrix-agora`.
- **Contract:** the `panel` service's mounts and env — ARCHITECTURE + `tests/test_compose.py`.

**Dependencies:** AGORA-039

**Expected result:**
Inside the panel container `docker compose -p server -f $STACK_DIR/server/docker-compose.yml config -q` works against
the real stack.

**Acceptance criteria:**
- [ ] The image builds with `docker` + `docker compose`; a local run of `docker compose version` in it works
- [ ] **Tests:** compose (the stack mount at the host path, read-only; `state/` read-write; the env), image (the CLI binaries come from official images by `COPY --from`)
- [ ] **Contract:** the panel's mounts + env — ARCHITECTURE updated
- [ ] **Gates:** lint, tests, compose
