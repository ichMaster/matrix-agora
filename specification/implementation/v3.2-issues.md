## v3.2 — Agent images, CI/CD and server deployment

### AGORA-028 — Single-instance lock, rotating file log, tzdata

**Description:**
Make the agent safe to run unattended in a container: a second instance of the same agent refuses to start,
logs also go to a rotating file the v3.3 panel can tail, and time zones work in a slim image. Touches
`agents/agent.py`, a small `agents/runtime.py`, `pyproject.toml`, tests.

**What needs to be done:**
- `agents/runtime.py`: `acquire_lock(path) -> lock | None` — `fcntl.flock(LOCK_EX | LOCK_NB)` on
  `state/<name>.lock`, the PID written inside; held for the process lifetime. `setup_logging(name)` — console
  + `state/logs/<name>.log` via `RotatingFileHandler` (1 MB × 3), the same format as today.
- `agent.py main()`: logging first, then the lock; a held lock → log `another instance is running (pid N)`
  and exit 1 before any login or sync.
- `tzdata` as a runtime dependency (zoneinfo in `python:*-slim` has no system tz database).
- The logs keep the existing rule: events only — no tokens, passwords or message/summary/memory texts.

**Dependencies:** None

**Expected result:**
Starting the same agent twice leaves the second one exiting with a clear message; logs appear in
`state/logs/<name>.log` and rotate at 1 MB.

**Acceptance criteria:**
- [ ] A second `acquire_lock` on the same file returns `None` while the first is held; after release it succeeds; the PID is in the file
- [ ] `main()` exits 1 on a held lock without logging in
- [ ] Logs go to console and `state/logs/<name>.log` (1 MB × 3)
- [ ] **Tests:** lock acquire / refuse / release (two descriptors in one process), PID content, the rotating handler's size and backup count, `main()` refusing on a held lock (nio mocked, no network)
- [ ] **Gates:** lint, tests

### AGORA-029 — The agent image: Dockerfile + .dockerignore

**Description:**
One image for both agents (`agents/Dockerfile`), with nothing secret in it. Touches `agents/Dockerfile`,
`.dockerignore`, tests.

**What needs to be done:**
- `agents/Dockerfile`: `python:3.12-slim` + uv; `uv sync --frozen --no-dev`; copy `agents/` (code, canons,
  life stories, TOMLs); `WORKDIR /app`; entrypoint `python agents/agent.py`, the TOML as the command
  (`agents/ada.toml`); `TZ` comes from the environment; `state/` is a mount point, never baked in.
- `.dockerignore` excludes `.env`, `server/.env`, `server_con.yaml`, `state/`, `reports/`, `.venv/`,
  `.git/`, `tools/`, `.claude/`, caches.
- Local build check: `docker build -f agents/Dockerfile -t matrix-agora-agent .`, and the built image holds no
  `.env`, `state/` or `server_con.yaml`.

**Dependencies:** AGORA-028

**Expected result:**
`docker build` produces a runnable image whose filesystem contains no secrets or state.

**Acceptance criteria:**
- [ ] The image builds locally and `docker run --rm <image> --help`-style smoke start fails only for missing env (no crash on import)
- [ ] **Tests:** a test pins `.dockerignore` (every secret / state path listed) — "the image holds no secrets"
- [ ] **Gates:** lint, tests, a local `docker build`

### AGORA-030 — Compose services ada / bruno / usage-report; deploy pulls

**Description:**
The stack on the server gains one service per agent from the same image, plus the daily token report
(v3.1.1) as a small service; `server/deploy.sh` pulls images before `up -d`. Touches
`server/docker-compose.yml`, `server/.env.example`, `server/deploy.sh`, `agents/usage_daily.py`,
`specification/ARCHITECTURE.md`, tests.

**What needs to be done:**
- `ada` and `bruno`: `image: ghcr.io/ichmaster/matrix-agora-agent:${AGENT_IMAGE_TAG:-latest}`,
  `command: agents/<name>.toml`, `env_file: .env`, `environment: HOMESERVER=http://homeserver:8008`,
  `TZ=${TIMEZONE:-Europe/Kyiv}`, `user: "1000:1000"`, `volumes: ../state:/app/state`,
  `stop_grace_period: 30s`, `restart: unless-stopped`, `depends_on: homeserver`.
- `usage-report`: the same image, `agents/usage_daily.py` — sleeps until the next 07:00 in `TIMEZONE`, then
  writes `reports/usage/YYYY-MM-DD.md` + `latest.md` (the v3.1.1 `daily_report`); mounts `../state` read-only
  and `../reports`. `next_run(now, hour)` is pure.
- `server/.env.example`: the agent variables (the same names as `.env.example`, plus `AGENT_IMAGE_TAG`),
  values empty.
- `server/deploy.sh`: `docker compose pull` before `up -d` (both with the `sudo -n` fallback), `--dry-run`
  prints it; it keeps syncing only `docker-compose.yml` and `server/.env`.
- **Contract:** the compose service set (`homeserver`, `ada`, `bruno`, `usage-report`), the `state/` and
  `reports/` mounts, the `server/.env.example` names and what `deploy.sh` applies — ARCHITECTURE §Contracts,
  §Deployment and CI/CD and §Repository layout updated; pinned by a test that parses the compose file
  (services, image, mounts, `HOMESERVER` override, grace period) and compares `server/.env.example`'s agent
  keys with `.env.example`.

**Dependencies:** AGORA-029

**Expected result:**
`docker compose config` shows the four services; a deploy pulls the agent image and starts both agents and
the report service next to the homeserver.

**Acceptance criteria:**
- [ ] Compose defines `ada`, `bruno`, `usage-report` as above; the homeserver block is unchanged
- [ ] `deploy.sh` pulls before `up -d`; `--dry-run` shows both
- [ ] **Tests:** the compose contract test; `.env.example` ↔ `server/.env.example` key parity; `next_run` (before / after 07:00, DST switch) with an injected clock
- [ ] **Contract:** compose service set + mounts + `server/.env.example` names + deploy steps — ARCHITECTURE updated, the compose test pins it
- [ ] **Gates:** lint, tests, compose

### AGORA-031 — CI: gates, image build, GHCR push

**Description:**
GitHub Actions runs the same gates as the Mac and builds the image on every push and PR, and publishes it to
GHCR with `GITHUB_TOKEN` only. Touches `.github/workflows/ci.yml`, `specification/ARCHITECTURE.md`, tests.

**What needs to be done:**
- Jobs: `uv sync` → `ruff check` → `pytest`; the compose gate; `docker build` of `agents/Dockerfile`.
- Publish to `ghcr.io/ichmaster/matrix-agora-agent`: on a `vA.B.C` tag → `:vA.B.C` + `:latest`; on a push
  to `main` → `:edge` + `:sha-<short>`. (`:edge` is how the server runs a phase's code before its release tag
  exists — the DoD needs the agents live before `vA.B.0`; the ARCHITECTURE CI paragraph records it.)
- `permissions: contents: read, packages: write`; no secrets other than `GITHUB_TOKEN`; no paid API keys.
- The GHCR package must be pullable by the server without credentials: the owner sets the package to
  public once (GitHub → Packages → matrix-agora-agent → Change visibility), if it is not already.

**Dependencies:** AGORA-029

**Expected result:**
A push to `main` runs lint, tests, the compose gate and the image build, and publishes `:edge`; a tag
publishes `:vA.B.C` and `:latest`.

**Acceptance criteria:**
- [ ] CI is green on a push to `main`; the image appears in GHCR as `:edge`
- [ ] **Tests:** a test reads the workflow and pins that the only secret referenced is `GITHUB_TOKEN`
- [ ] **Gates:** lint, tests; CI itself
- [ ] **Manual (owner):** the GHCR package is public (or confirmed pullable from the server without login)
- [ ] **Manual (owner):** pushing a `vA.B.C` tag publishes the image to GHCR (checked at the v3.2.0 release)

### AGORA-032 — Server cut-over: state migration, deploy, live DoD

**Description:**
Move the running agents from the Mac to the server without losing their sessions or memories, and verify
the phase DoD live. Claude runs the steps over SSH (key auth); the owner confirms the conversation checks.
Produces a local `server/.env` (gitignored).

**What needs to be done:**
- `server/.env` (local, gitignored): the host's `REGISTRATION_TOKEN` (copied from the host, never printed)
  + the agent values from the Mac `.env` + `AGENT_IMAGE_TAG=edge` until the release, then `latest`.
- Stop the Mac agents gracefully (`SIGTERM` → session summaries), uninstall the Mac usage job
  (`scripts/install-usage-daily.sh --uninstall`).
- Copy `state/` to `~/matrix-agora/state/` on the host (rsync over SSH, owned by uid 1000); create
  `~/matrix-agora/reports/`.
- `server/deploy.sh --dry-run`, then `server/deploy.sh`; check `docker compose ps` and the agents' logs
  (`joined`, `entering sync_forever`).
- Read-only checks Claude can run: containers up, `state/logs/*.log` growing on the host, no new device
  (the sessions are reused), `docker stop -t 30 ada` → the summary log line before exit, then start it again.

**Dependencies:** AGORA-030, AGORA-031

**Expected result:**
Ada and Bruno run on the server from the GHCR image, remember everything from the Mac, and the Mac runs no
agents.

**Acceptance criteria:**
- [ ] `server/.env` exists locally, gitignored, never printed; the Mac agents stopped; the Mac usage job uninstalled
- [ ] `~/matrix-agora/state/` on the host holds the migrated files and fills in
- [ ] **Manual (owner):** after `server/deploy.sh`, both agent containers run on the server, join the room and reply
- [ ] **Manual (owner):** `docker stop -t 30 ada` on the server → Ada's session summary is written before the container exits
- [ ] **Manual (owner):** dev mode on the Mac still works against the same homeserver (with the server's agent stopped for the test — the lock is per host)
- [ ] The image holds no secrets; env and `state/` come only from the host
- [ ] **Gates:** compose (deploy preflight)
