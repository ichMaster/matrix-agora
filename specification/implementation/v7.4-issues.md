# v7.4 — Issues

Issues for phase **v7.4 — The companions' five models: Кіра and Устина switched in the panel** (version **v7 —
Claude for everyone: every agent on the owner's subscription**), derived from the Tasks and DoD in
[ROADMAP.md](../ROADMAP.md) §v7.4 and the contracts in [ARCHITECTURE.md](../ARCHITECTURE.md). This file covers one
phase; ids continue from the previous phase (AGORA-249 → **AGORA-250…254**).

Кіра's and Устина's answers — the private chat, writing first, Agora — come from the model the owner picks in each
one's panel settings: Gemini 3.1 Pro, GPT-6.1 Sol and Sonnet on their APIs, Opus on the Max plan, GPT-6.1 Sol through
Codex on the ChatGPT plan, each thinking. It builds on v7.3.4 (both companions on Gemini, the v7.3 code for Claude
kept) and replaces the planned «Устина on Claude»; the prompt's order for the cache stays v7.5's, the panel's
subscription analytics v7.6's.

**Reconciled with the code (2026-11-11):**
- **The seam exists.** `_compose` → `self.responder.respond(Turn(...))` → `LlmResponder`, which sends `ANSWER_KINDS`
  (`reply`, `private`, `private_nudge`) to `llm.reply(transcript, system, max_output_tokens, kind)` → `(text, finish)`
  and every other kind to `complete` (`agents/responder.py`). A refusal is `None` with `LAST_BLOCK` set
  (`("refusal", …)` on Claude, `("prompt" | "answer", …)` on Gemini), which `_private_text` already sends to the
  backup. So the switch is a responder over five answer clients, the background left on the agent's `self.llm`
  (Gemini).
- **The prompt goes whole.** Every answer client takes the system instruction whole as its system prompt and the
  transcript as the message, as Gemini does now and the Claude CLI since 7.3.3 (`CLAUDE_WARM=off`). ROADMAP §v7.4's
  «its slow part the system and the rest the message» is corrected in AGORA-253; the order for the cache is v7.5's.
- **Opus gets its own effort.** `CLAUDE_EFFORT` (scope `client:claude-sdk`, default `low`) is the room's and Hermes's.
  The companions' Opus reads `OPUS_EFFORT` (default `high`), so ROADMAP's «`CLAUDE_EFFORT` `high`» is corrected in
  AGORA-253.
- **Secrets are taken out at the start.** `Agent.__init__` pops each secret into a local before anything can inherit
  it (`ELEVENLABS_API_KEY`, `TELEGRAM_BOT_TOKEN`, `DEEPGRAM_API_KEY`, `FAL_KEY`, the NovelAI token). `OPENAI_API_KEY`
  and `SONNET_API_KEY` (already in the local `server/kira.env` and `server/ustyna.env`) join them.
- **What the Claude CLI inherits.** `claude_client_for` refuses `ANTHROPIC_*` (`check_startup`), scrubs, and pops
  every `*_KEY` / `*_TOKEN` / `*_PASSWORD` but the OAuth token from `os.environ`, since the CLI inherits the whole
  environment. On a Gemini-engine companion her photo and clip makers build their own `genai.Client()` from
  `GEMINI_API_KEY` in the environment (`_media_gemini` is None on Gemini). With a Claude CLI in the same process,
  they take the Gemini client's SDK client instead, as on Claude (v7.3).
- **The compose contract changes.** `claude_service_problems` (`tests/test_compose.py`) requires a service on `gemini`
  never to load `subscription.env`. A companion with the switch runs on the Claude image with `subscription.env`, and
  that check now holds by the switch, not only by the engine.
- **Usage is by engine.** Lines are per engine (`usage_line` engine `gemini`, `sdk_usage_line` `claude-sdk`); the
  panel and the report group by it. API prices come from `PRICE_MODELS` (`model=in/out`).
- **The live switch is free.** `LIVE` switches are read at each use by `live_value(state_dir, agent, name, env)`;
  a save restarts nobody.

### AGORA-250 — The answer switch: `ANSWER_MODEL`, a responder over the answer clients, Gemini 3.1 Pro and Opus on Max

**Description:**
A companion's answers go to the model her panel setting names, read at each answer. This issue builds the switch with
the two clients that exist (Gemini 3.1 Pro, Opus on the Max plan) and the names that follow from it. Touches
`agents/settings.py`, `agents/responder.py`, `agents/agent.py`, `agents/claude_sdk.py`, `panel/memory.py`.

**What needs to be done:**
- **Settings** (`agents/settings.py`):
  - `ANSWER_MODEL`: a choice of `api-gemini-3.1pro` (the default), `api-gpt-6.1sol`, `api-sonnet`,
    `claudemax-opus`, `codex-gpt-6.1sol`. Scope `cap:private` (Кіра and Устина), group `model`, added to `LIVE`.
  - The thinking of each, read at the start:
    - `GEMINI_THINKING_LEVEL` as now (`low`; widened to concern a companion);
    - `OPENAI_REASONING_EFFORT` `low|medium|high`, default `medium`;
    - `SONNET_EFFORT` `low|medium|high|max`, default `medium`;
    - `OPUS_EFFORT` `low|medium|high|max`, default `high`;
    - `CODEX_REASONING_EFFORT` `low|medium|high`, default `medium`.
  - None of them offers `off`.
- **The switch** (`agents/responder.py`): `SwitchedResponder(choice, clients, base)`.
  - `choice()` is the live value. `clients` maps a choice to its answer client.
  - An `ANSWER_KINDS` turn goes to the chosen client's `reply`, every other kind to the base `LlmResponder` (Gemini).
  - A choice whose client is missing (no key, not signed in) is logged once a minute by name, and its answer is
    silence as a failed call is. Never another model.
- **The agent** (`agents/agent.py`):
  - A companion (`cap:private`) on `engine = "gemini"` gets the switch.
  - Behind `api-gemini-3.1pro`: her Gemini client as now.
  - Behind `claudemax-opus`: a `ClaudeClient` on the Max plan.
    - It is built by `claude_client_for` with `gemini=self.llm`, so there is no second Gemini client, and that Gemini
      client is the fallback at the limit.
    - Its reply model is `opus`, thinking adaptive at `OPUS_EFFORT`, `warm=False` (the whole instruction as the
      system, 7.3.3), the background never used.
  - Every secret is out of the environment before the client exists: v4.4's layers, `ANTHROPIC_*` refused.
  - Her photo and clip makers take the Gemini client's SDK client (as on Claude, v7.3), so no maker reads
    `GEMINI_API_KEY` from the environment.
  - `reply_max_tokens` is `REPLY_THINK_MAX_TOKENS` for a companion with the switch: every choice thinks, and the
    thinking counts in the cap.
- **Names** (`agents/agent.py`, `agents/claude_sdk.py`):
  - `served_by` and her answer's `by` name the engine that answered: `gemini`, `claude`, and later `openai`,
    `anthropic`, `codex`; the Gemini fallback at a limit is `gemini`.
  - `main_name()` is the chosen value (e.g. `claudemax-opus`) in `/status`, the commands' list and the ⚙️ lines.
  - `/gemini` and `/claude` both return from the backup to the chosen model; the route file's keys are unchanged.
  - `keep_prompt` records the chosen model.
- **The panel's card** (`panel/memory.py` `models_view`): for a companion, `answers` is the chosen model's id and
  `thinking` its level; `background` stays Gemini's.

**Dependencies:** None

**Expected result:**
In her panel the owner switches Кіра or Устина between Gemini 3.1 Pro and Opus on Max, and the next answer comes from
it, with no restart.

**Acceptance criteria:**
- [ ] `ANSWER_MODEL` validates its five choices, is live, and concerns Кіра and Устина alone.
- [ ] An answer kind goes to the chosen client and a background kind to Gemini; a save in `state/settings.json` takes

- [ ] On `claudemax-opus` the CLI's environment holds no secret but the OAuth token. A decline goes to the backup
  (v7.3), the Max limit to Gemini 3.1 Pro, and the ⚙️ line names the chosen model.
- [ ] **Tests:**
  - the switch with fake clients: answer vs background kinds, the live change, a missing client is silence;
  - her photo makers on the Gemini client's SDK client, nothing read from the environment;
  - `by`, `main_name`, `/gemini` and `/claude`;
  - the panel's models view;
  - no network.
- [ ] **Contract:** the env var names (`ANSWER_MODEL` and the four efforts) and the answer line's `by` values in
  ARCHITECTURE §Contracts, pinned by `tests/test_settings.py` and the answers tests.
- [ ] **Gates:** lint, tests.

### AGORA-251 — GPT-6.1 Sol and Sonnet on their APIs: two answer clients, their keys, refusals and usage lines

### AGORA-252 — GPT-6.1 Sol through Codex on the ChatGPT plan: `codex exec`, no tools, no API key, its limit

answer; the answer only. New `agents/codex_cli.py`; touches `agents/agent.py`, `agents/usage.py`, `agents/Dockerfile`.

    0600, removed after the call). Otherwise her whole prompt is the message — measured, and written in the report.
  - The transcript goes in by stdin, never on argv.

  show a tool call is a failed answer and is logged.
- **Never an API key:**
  - The login is forced to ChatGPT.
  - The CLI gets an explicit environment with no secret: no `OPENAI_API_KEY`, no `SONNET_API_KEY`, no other key.
  - A run that reports any other authentication blocks the client until a restart, as Claude's
    `apiKeySource` check does.
- **Its credentials:**
  - `CODEX_HOME` = `state/<name>.codex/` (0700), one per companion. The owner signs each in once (AGORA-254).
  - They are never printed, logged, put in an image or put in a test.
- **What comes back:** the final message from the JSON events, its usage, its limits.
  - At a ChatGPT limit the answer goes to her Gemini 3.1 Pro (v7.1's `gemini` at the limit), as at the Max limit.
  - A refusal is a `LAST_BLOCK` refusal; a timeout (`CODEX_TIMEOUT_S`) is a failed call.
- **Usage:** engine `codex`, billing `subscription`, the tokens it reports, `latency_ms`.
- **The image:** the Codex CLI binary in the Dockerfile's `claude` target, pinned by version and checksum. The
  `agent` target is unchanged.
- **The switch:** `codex-gpt-6.1sol` registered when the CLI is present. Without credentials it is a missing choice
  (AGORA-250), logged as «not signed in».

back to Gemini 3.1 Pro at its limit.
