# Agora Panel — design brief

A brief for mocking up the web panel of **matrix-agora** in Claude Design. Mockups are generated by hand from
this brief; the implementation follows them in phases v3.3 (viewing) and v3.4 (control) — see
[ROADMAP.md](../ROADMAP.md) §v3.3–v3.4 and [ARCHITECTURE.md](../ARCHITECTURE.md) §The panel.

---

## 1. What it is

A private control room for **agent simulations**. Today there is one simulation — **Agora**, a private
Matrix chat room on a home server where the owner talks with two AI characters, **Ада** and **Бруно**, who
live their own lives in Lviv (memories, plans, a daily routine). The panel shows the simulation, the
characters connected to it, what they remember and plan, what they cost, and the health of the server — and
from v3.4 it starts, stops and restarts them.

It will grow: later there will be more simulations and more characters, so the layout must treat "the chat"
as **one simulation in a list**, not as the whole app.

## 2. Who uses it, where

- **One user: the owner.** Technical, Ukrainian-speaking. No accounts, no roles.
- **Where:** a desktop browser on the home network (main), sometimes a phone on the same Wi-Fi.
- **How often:** glanced at a few times a day ("are they alive, what did they do, what did it cost"),
  occasionally used to act (restart someone, read a log after a problem).
- **The UI language is Ukrainian.** All copy in the mockups in Ukrainian (see §9).

## 3. Constraints the design must respect

- **One static page**: plain HTML + CSS + vanilla JavaScript served by a small FastAPI app. No framework, no
  build step. Design with components that are easy to hand-write: cards, tabs, tables, a drawer or modal,
  a toast.
- **Light and dark themes**, both first-class.
- **Works at 1440 px and at 390 px** (phone): cards reflow to one column; tables scroll inside their card.
- **System fonts are fine**; at most one webfont. Logs and technical values in a monospace font.
- **No secrets on screen, ever.** Settings appear read-only with any `*_KEY`, `*_PASSWORD`, `*_TOKEN` masked
  as `••••••`. There are no forms that edit configuration or the characters' personalities.
- **It is not a chat client.** The panel never shows or sends chat messages; the owner talks to the
  characters in Element. (It does show the characters' memories, plans and session summaries.)
- Data refreshes every ~5–30 s; design calm "updated 12 s ago" indicators, not spinners everywhere.

## 4. Information architecture

```
Top bar:  Агора · панель        [server status pill]   [updated 12 s ago ⟳]   [theme]   [вийти]

Section 1 — Симуляції        one card per simulation (today: one — "Агора", kind matrix-chat)
Section 2 — Агенти           one card per character (Ада, Бруно), grouped under their simulation
Section 3 — Сервер           host card (uptime, disk, memory, load)
Section 4 — Токени           7-day usage table + totals and cost

Agent detail:  a side drawer (desktop) / full screen (phone) with tabs
Log viewer:    a drawer or modal with a monospace tail and a "follow" toggle
```

Suggested desktop layout: a 12-column grid — the simulation card full width on top, the two agent cards side
by side, then the host card and the usage table side by side. Feel free to propose a better one (e.g. a
narrow left nav listing simulations, ready for more than one).

## 5. Screens and states to mock

Please produce each in **light and dark**, desktop (1440) unless noted.

1. **Token gate.** Centered card: title, one password-style field "Токен власника", button "Увійти", a short
   note that the panel is LAN-only. Error state: "Невірний токен". Without a valid token the page shows
   nothing else.
2. **Dashboard — everything healthy** (the main mockup). Both agents running, simulation healthy.
3. **Dashboard — phone (390).** The same content, one column.
4. **Agent detail drawer** for Ада, with tabs:
   - **Журнал** — the log tail (monospace, event lines, newest at the bottom, "follow" toggle).
   - **Остання сесія** — the last session summary (a paragraph) + when it was written.
   - **Спогади** — day memories as a list by date (newest first), each expandable; above them the digest
     layers (week / month / year) as compact rows.
   - **Плани** — four horizons: Рік, Місяць, Тиждень, День — each a short bulleted list.
   - **Сьогодні** — the hourly "today" block (a short paragraph) + "оновлено о 14:00".
   - **Токени** — this agent's 7-day calls and tokens by kind.
5. **Log viewer** for the homeserver service (opened from the simulation card).
6. **Degraded states** (can be one dashboard with mixed states, or separate frames):
   - the homeserver is down → simulation health red "Недоступна", agents show "перепідключається";
   - Docker is unreachable → container cards greyed with "Docker недоступний — стан невідомий";
   - `state/` unreadable → memory tabs greyed "Пам'ять недоступна";
   - an agent stopped; an agent whose container does not exist yet ("контейнер не створено");
   - an agent running in a terminal on the Mac instead of the server ("запущено в терміналі (Mac)").
7. **Control (v3.4)** — the same dashboard with actions:
   - on each agent card: Запустити / Зупинити / Перезапустити, and in the drawer "Забути останню сесію";
   - on the simulation card, per service: Запустити / Зупинити / Перезапустити;
   - a **confirmation dialog** for stop / restart / forget (texts in §9);
   - an action in progress (the button busy, the status "зупиняється… пише підсумок сесії") and a result toast.
8. **Empty / loading**: first load skeletons; an empty usage table ("Ще немає даних").

**Phasing:** v3.3 ships screens 1–6 with no action buttons at all; v3.4 adds screen 7. If possible, show the
agent card in both variants (view-only and with actions).

## 6. The components, with their data

### Simulation card
- Title **Агора**, kind badge `matrix-chat`, a one-line description ("приватна кімната Matrix · agora.lan").
- Health: status pill (**Працює** / **Недоступна** / **Невідомо**), probe latency "42 мс", "перевірено 18 с тому".
- Services list (today one row; design for 1–5 rows): name `homeserver`, image short name `continuwuity`,
  state **працює**, uptime "39 год", a "Журнал" link; v3.4: start/stop/restart icon buttons.
- Agents in this simulation: "2 агенти · обидва працюють".

### Agent card (×2)
- Avatar: initials or a simple monogram (no photos) — **А** for Ада, **Б** for Бруно. Name + one-line role:
  - **Ада** — «редакторка, 32, Львів»
  - **Бруно** — «звукорежисер, 35, Львів»
- State pill: **працює** / **зупинено** / **перепідключається** / **контейнер не створено** /
  **запущено в терміналі**. Where it runs: "сервер · контейнер `ada`" or "Mac · термінал".
- Uptime "2 год 14 хв", last activity "відповіла 3 хв тому", session "активна сесія: 6 повідомлень" or
  "сесія завершена о 13:26".
- Today's one-liner (first line of the today block), e.g. «Неділя: книжка, кава й прогулянка старим містом».
- 7-day tokens mini figure: "214 викликів · 1,3 млн токенів · $0,46".
- Buttons: "Деталі" (drawer); v3.4: Запустити / Зупинити / Перезапустити.

### Host card
- Uptime "39 год", Disk "32 ГБ вільно з 98 ГБ" (bar), Memory "2,1 / 7,7 ГБ" (bar), Load "0,12 · 0,20 · 0,18",
  Containers "4 працюють". OS line "Ubuntu · 192.168.1.197".

### Usage card (7 days)
- A compact table: **день · агент · тип · виклики · вхід · вихід · вартість $**, totals per agent and overall,
  and a small per-day bar or sparkline of total tokens. Kinds: `reply`, `summary`, `plan`, `day_memory`,
  `digest`, `today`. Cost column only when prices are configured (design the table with and without it).
- Sample rows (realistic scale):

  | день | агент | тип | виклики | вхід | вихід | вартість $ |
  |---|---|---|---:|---:|---:|---:|
  | 2026-10-03 | ада | reply | 41 | 270 115 | 2 104 | 0,0863 |
  | 2026-10-03 | ада | summary | 3 | 21 870 | 610 | 0,0081 |
  | 2026-10-03 | бруно | reply | 37 | 248 402 | 2 377 | 0,0805 |
  | 2026-10-03 | бруно | plan | 4 | 9 240 | 980 | 0,0052 |
  | **разом** | | | **85** | **549 627** | **6 071** | **0,1801** |

### Log tail (sample lines — events only, never message texts)
```
13:26:02 agent INFO ada: session restored (device ABCDEF1234)
13:26:02 agent INFO ada: context seeded with 30 room messages
13:26:03 agent INFO ada: entering sync_forever
13:41:17 agent INFO reply: owner-mentioned-me (in 2.4s)
13:41:22 agent INFO ignored: own-message
13:52:40 agent INFO paused: streak-limit; resume check in 593s
14:00:05 agent.memory INFO saved state/ada.today.md (96 words)
```

### Memory and plans (sample content, invented for the mockup — not real agent data)
- **Остання сесія:** «Говорили з Ich про те, які книжки брати в дорогу, і про перший осінній дощ. Бруно
  розповідав про нову гітарну педаль, Ада радила йому почитати щось легке на вихідні.»
- **Спогад за 3 жовтня:** «Зранку редагувала довгий переклад і нарешті приборкала речення на пів сторінки.
  Після обіду — кава в маленькій кав'ярні біля Ратуші, ввечері прогулянка під ліхтарями.»
- **Плани — День:** «здати редактуру перекладу до п'ятниці» · «купити лампу для читання» · «домовитися з
  подругою про суботу».
- **Сьогодні:** «Неділя, 14:00. Повільний день: книжка, кава, трохи роботи над текстом. Увечері — прогулянка
  старим містом.»
- (Optional, owner-only insight) a plan item may carry a subtle tag **«відхилення»** — the plan deviates from
  the character's life story. Design it as a quiet badge; it is never shown to the characters themselves.

## 7. Status vocabulary

| Meaning | Ukrainian label | Treatment |
|---|---|---|
| running / healthy | працює | green dot + text |
| working right now (answering, writing memory) | працює… / пише підсумок | blue, subtle pulse |
| reconnecting / degraded | перепідключається | amber |
| stopped (on purpose) | зупинено | neutral grey |
| down / error | недоступна | red |
| unknown (no data source) | невідомо | grey, dashed outline |
| not created yet | контейнер не створено | outline only |

Never color alone — always a dot/icon **and** the word. Meet WCAG AA contrast in both themes.

## 8. Visual direction

- **A calm operations console for a small private world.** Quiet, legible, dense enough to see everything on
  one 1440 screen without scrolling the main view; generous only where people read (memories, plans).
- Warm neutrals rather than cold blue-grey; one accent color. A light nod to the place — an old city at
  dusk, a town square ("agora") — is welcome in the token gate or the empty states, never in the data views.
- Cards with clear headers, small caps or muted labels, tabular numbers in tables, monospace for logs and ids.
- Do **not** use the logos or branding of Matrix, Element, Google/Gemini, Docker or Anthropic.
- Character avatars: monograms or abstract shapes — no faces, no photos.

## 10. Deliverables

1. Token gate (+ error) — light, dark.
2. Dashboard, healthy — 1440, light and dark.
3. Dashboard, phone — 390, light or dark.
4. Agent drawer, all six tabs (can be one frame per tab, or one frame + tab variants).
5. Log viewer.
6. Degraded states (one or more frames).
7. v3.4 control: agent card with actions, confirmation dialog, action in progress, toast.
8. A small component sheet: status pills, buttons, card header, table row, tabs, toast, dialog — with the
   colors and type scale used, so the page can be hand-built in plain CSS.
